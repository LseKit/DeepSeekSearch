>
> **为什么 domain 需要 `crypto/rand`**：`WrapUntrusted` 的随机 nonce 定界符（见 `12-数据契约` §七）。MUST NOT 用 `math/rand/v2` —— 那可预测，攻击者能猜到 nonce 从而伪造闭合标签。

### 2.10.1 🔴 「4 个第三方」的精确口径（此前三个文档各说一套）

全项目**运行时**第三方依赖固定为 **4 个**：mcp go-sdk、BurntSushi/toml、joho/godotenv、modernc.org/sqlite。

另有 **1 个仅测试**依赖：`github.com/google/go-cmp/cmp`（`21-测试规范` §二 与 `19-AGENTS.md全文` T8 允许用它做断言）。

还有 **4 个仅开发期**工具依赖，经 `go.mod` 的 `tool` 指令登记（`Task-01` A-01 §3 第 2.1 条）：`mvdan.cc/gofumpt`、`github.com/golangci/golangci-lint/v2`、`github.com/fzipp/gocyclo`、`golang.org/x/vuln`。它们的**传递依赖**会写进 `go.mod` 的 `require`（约 10KB、上百条 indirect），但**不进二进制**。
⚠️ 因此「`go.mod` 里不许有 `require`」是一句**错误**的判据 —— 它与 `tool` 指令互斥。正确判据是「非测试代码 import 的第三方包只有 4 个」，即 `go list -deps ./... | grep -E '^[a-z0-9.-]+\.[a-z]{2,}/'` 的结果集合。

| 口径 | 数量 | 判据 |
|---|:-:|---|
| 运行时（进二进制、进 SBOM 的 runtime scope） | **4** | §三 的 AR-1 只扫**非 `_test.go`** 文件（见下表第 1 步），所以它天然只约束这 4 个 |
| 仅测试（进 `go.mod`，**不进**二进制） | **1**（go-cmp） | AR-1 扫不到；由 code review 与「MUST NOT 引入 testify」这条禁令约束 |

**为什么这个区分 MUST 写出来**：原文只说「固定为 4 个」，而 21 号与 19 号又允许 go-cmp ⇒ `go.mod` 里必然出现第 5 个 require。实现者遇到这个矛盾只有两种走法，都是错的：① 以为 21 号写错了，手写一堆 `reflect.DeepEqual` + 自己拼 diff（丢掉 go-cmp 的全部价值）；② 以为 10 号写错了，往业务代码里也引 go-cmp（真正破坏 4 个的约束）。

**边界（MUST 遵守）**：
- go-cmp **只能**出现在 `_test.go` 里。业务代码引入它 = 运行时依赖变成 5 个，AR-1 会当场红。
- SBOM MUST 标出 scope，`govulncheck` 报 go-cmp 的漏洞时按「不可达（test-only）」处置，MUST NOT 当作发版阻塞 —— 但 MUST 记进 `16-技术债登记表` 跟踪升级。
- README 宣传「只有 4 个第三方依赖」时 MUST 写明是**运行时**口径，否则 `go.mod` 一打开就是 5 行 require，宣传变成假话。

## 四、为什么这样切（每条一句话理由）

| 切分 | 理由 |
|---|---|
| `domain` 无任何内部依赖 | 它是全项目的词汇表，被所有人 import，不能再依赖任何人 |
| `domain` 不用 `net/http` | 一旦 import，纯函数就绑上了传输层，测试要起 httptest |
| `config` 依赖 `domain` 而不是反过来 | 配置项的值域定义（如 `detail` 枚举）属于领域知识 |
| `deepseek` 不 import `mcp` | 上游契约与协议解耦，换协议不用动 HTTP 层 |
| `logging` 不 import `resilience` | `Clock` 用参数传，避免 `logging ↔ resilience` 成环 |
| `resilience` 不看 `http.Response` | 重试决策只应基于错误**分类**。这样它将来也能用于非 HTTP 的上游 |
| `resilience/cache` 同时承载缓存与 singleflight | 两者共享 SQLite 租约表、storage key 与 oversize 标记；拆成两个包会把 `leaseBackend` 的 6 个内部方法提升为导出 API |
| `resilience` 根包只放接口与共享类型 | 五个实现子包都依赖根包的 `Clock`/`Config`/接口，根包不依赖任何子包，因此拆开后没有环；「五项能力一个包」的 F-S5 例外随 `DEBT-010` 清零退出 |
| `resilience` 子包之间不互相 import | 限流、重试、预算、熔断、缓存各自独立；共享逻辑只允许下沉到根包，MUST NOT 让 `ratelimit → cache` 这类边出现 |
| `tools` 是唯一同时知道 `mcp` 和 `deepseek` 的包 | 它是「翻译层」：MCP 参数 → 上游请求，上游结果 → MCP content。适配器天然需要一个交汇点 |
| `transport` 不认识 `tools` | 传输只负责把 `*mcp.Server` 挂上通道，不关心里面注册了什么工具 |
