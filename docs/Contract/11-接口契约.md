## 零、模块路径与版本注入点

```go
// go.mod
module github.com/LseKit/DeepSeekSearch

go 1.27
```

版本号唯一真源是 `cmd/deepseeksearch/version.go` 里的三个变量，**由 `-ldflags` 注入**，代码里有兜底默认值：

```go
package main

// 这三个变量只能由链接器注入。MUST NOT 从 config.toml 读取。
// 构建命令见 17-版本与发布契约.md；不注入时显示开发版。
var (
    version   = "v0.0.0-dev"           // -X main.version=v0.1.0
    commit    = "none"                 // -X main.commit=a1b2c3d
    buildTime = "unknown"              // -X main.buildTime=2026-10-20T13:05:12Z
)
```

`BuildInfo` 结构体在 `domain` 包定义，供 `serverInfo`、`/healthz`、`--version` 三处共用（**同一个值，不许各算一遍**）：

```go
package domain

// BuildInfo 是编译期信息的不可变快照。
type BuildInfo struct {
    Version   string // 语义化版本，如 "v0.1.0"
    Commit    string // git short sha，7 位
    BuildTime string // RFC3339 UTC
    GoVersion string // runtime.Version()
}
```

## 一、Domain 层（纯类型，无接口）

Domain 包只定义一个最小接口 `Coded`（能自报错误码），其余是类型、枚举、纯函数与错误值。详见 `12-数据契约.md`。

**导出清单**（其余一律不导出）：

| 类别 | 符号 |
|---|---|
| 请求/响应 | `SearchRequest` `SearchResponse` `SearchResult` `FetchRequest` `FetchResponse` `Section` `Outline` |
| 时间 | `PublishedDate` |
| 错误 | `UpstreamError` `ValidationError` `LocalError` `ErrorPayload` `CodeInfo` `Coded`（接口） |
| 错误码 | `CodeXxx` 常量 42 个（见 `14-错误契约.md`）+ `CodeRegistry map[int]CodeInfo`（长度同为 **42**，含软错误 1080） |
| 版本 | `BuildInfo` |
| 纯函数 | `ParseDate(s *string, now time.Time) PublishedDate` `NormalizeUrl` `HashUrl` `RedactURL` `RedactSecrets` `Unescape` `SliceByRune` `TruncateRunes` `TruncateUntrusted` `ClipBytes` `WrapUntrusted` `NormalizeTitle` `BuildQuery` `SplitSections(content string, fixedChunk int) Outline` `Dedupe(items []SearchResult, maxPerDomain int, trackingParams []string) ([]SearchResult, DedupeStats)` `SnapshotID(rawURL string, capturedAt time.Time) string` `NewCallID() string` |
| 错误辅助 | `CodeOf(err) int` `IsRetryable(err) bool` `ToPayload(err error, tool string) ErrorPayload` `UpstreamTypeOf(err error) string` `AppendUpstreamType(args []any, err error) []any` |
| 上下文辅助 | `ContextWithAttempt(ctx, n) context.Context` `AttemptFromContext(ctx) int` |
| 错误构造 | `NewUpstreamError` `NewUpstreamParseError` `NewNetworkError` `NewValidationError` `NewLocalError` |

> 🔴 **`ToPayload` 的 `tool` 参数只用于 2404 的 hint 分流**（`14-错误契约` §2.3.1）：`ds_search` 的 404 = `base_url` 配错，`ds_fetch` 的 404 = 取不到正文，两套 hint 给的动作完全不同。取值为 `"ds_search"` / `"ds_fetch"` / `"ds_health"`；传空串按 `ds_fetch` 处理。
>
> 🔴 **`RedactURL(raw, keys)` 无条件剥掉 userinfo**（2026-10-25 审计）：`ds_fetch` 的 URL 由调用方给，带 `user:pass@` 的 URL 在参数校验**之前**就会进 `call.begin` 日志，而密码对排查毫无用处。`keys` 为空时同样要剥（早期实现 `len(keys)==0` 直接原样返回，等于漏掉凭据）。
>
> 🔴 **`Section` 带 `Start`（本节正文在整篇里的 rune 偏移）**，消费方 MUST 用 `Start` 取正文，MUST NOT 累加各节 `Chars` 推偏移：纯空白前言不生成节，累加会让其后每一节整体错位（取到上一节的尾巴、末尾一节永远取不到）。
>
> 🔴 **`ErrUpstream` / `ErrValidation` / `ErrLocal` 已从清单移除**：全库无任何语义定义与引用，错误分类由**具体类型 + 错误码**承担。保留没有语义的哨兵名，只会诱导实现者去发明用法。

**错误构造函数的包归属（E9 裁决）**：全部归 `domain`，MUST NOT 分散到 `deepseek`/`tools`。理由：它们产出的是 `domain` 的错误类型，而 `domain` 是叶子包 —— 放在 `deepseek` 会让 `resilience`/`tools` 为了构造一个 2999 而反向依赖上游客户端，直接违反 `10-包依赖矩阵.md` 的不变式。

```go
// NewUpstreamParseError 构造「上游 200 但响应体不可解析」的错误（2999）。
// 单独导出是因为它不在 HTTP 错误路径上，没有 status 可映射。
func NewUpstreamParseError(bodyLen int, cause error) error

// ContextWithAttempt / AttemptFromContext 传递「这是第几次尝试」（1 起算）。
// 🔴 MUST 放 domain 而不是 resilience：`10-包依赖矩阵` §2.4 禁止 deepseek import
// resilience（会与「Resilience 包裹 Client」形成循环依赖）。domain 是二者共同的叶子依赖。
func ContextWithAttempt(ctx context.Context, n int) context.Context
func AttemptFromContext(ctx context.Context) int // 无值时返回 1

// NewNetworkError 构造「拿不到 HTTP 响应」的错误（2998，可重试）。
// cause MUST 是下列之一，会原样进 details.cause：
//   "dns" / "tcp_connect" / "tls_handshake" / "attempt_timeout" / "response_reset"
// attempt 从 1 起算，进 details.attempt。见 14-错误契约 §2.2 与 ADR-016。
func NewNetworkError(cause string, attempt int, err error) error
```

**`NormalizeUrl` 的签名（E5 裁决）**：追踪参数表是 `[dedupe].tracking_params` 配置项（默认 26 个），MUST NOT 在 domain 里硬编码 —— 否则「配置化」是假的。

```go
// trackingParams 由调用方从 config 注入；传 nil 表示「不剥离任何追踪参数」。
func NormalizeUrl(raw string, trackingParams []string) (string, error)
```

## 二、Config 层

```go
package config

// Config 是启动后不再变更的配置快照。
// 全部字段在 Load 中填充、在 Validate 中校验一次，运行期只读。
type Config struct {
    App        appConfig
    Server     serverConfig
    Upstream   upstreamConfig
    RateLimit  rateLimitConfig
    Timeout    timeoutConfig
    Retry      retryConfig
    Circuit    circuitConfig
    Limits     limitsConfig
    Cache      cacheConfig
    Dedupe     dedupeConfig
    Search     searchConfig
    Security   securityConfig
    Log        logConfig
}

// 🔴 段落类型**不导出**：外部消费者只经 Config 的字段访问（如 cfg.Server.Http.Host），
// 从不需要也不应该构造它们。导出它们会让 config 的公开面撑破 F-S5 的 20 个符号上限
// （2026-10-21 DEBT-010）。

// Load 按「环境变量 > Config/.env > config.toml > 内置默认值」优先级合并。
// 返回的 Config 已通过 Validate；任一项不合法则返回 error，调用方 MUST 直接退出。
func Load(configPath string, envPath string) (Config, error)

// LoadFromEnvOnly 只用环境变量 + 内置默认值构造配置。供 stdio 单机场景使用。
// 返回值同样已通过 Validate。
func LoadFromEnvOnly() (Config, error)

// Validate 单独导出，供测试与「配置检查」子命令复用。
// 一次收集全部错误；warnings 是允许启动但需要提示的项（由 cmd 打印）。
func (c Config) Validate() (warnings []string, err error)

// Source 返回某个配置项最终取自哪一层，供日志与 ds_health 展示。
// key 用点分路径，如 "ratelimit.search.rps"。未知 key 返回 SourceUnknown。
func (c Config) Source(key string) SourceKind

// SourceKind 标识配置来源层级。
type SourceKind string

const (
    SourceDefault SourceKind = "default"
    SourceFile    SourceKind = "file"
    SourceDotEnv  SourceKind = "dotenv"
    SourceEnv     SourceKind = "env"
    SourceUnknown SourceKind = "unknown"
)

// Redacted 返回可安全打印/外发的配置副本：ApiKey 与 HttpToken 替换为 "***"。
func (c Config) Redacted() Config
```

### 2.1 约定

| 项 | 规定 |
|---|---|
| 返回值 | `Load` MUST 返回**值**类型 `Config`，不是 `*Config`。避免调用方修改共享状态 |
| 错误 | MUST 用 `fmt.Errorf("config: %w", err)` 包裹，错误消息里 MUST 带**字段路径**（如 `ratelimit.search.rps`）与**行号**（能定位时） |
| 未知键 | MUST 用 `toml.Decoder.DisallowUnknownFields()` 等价能力拒绝，MUST NOT 静默忽略 |
| 不做的事 | Config 包 MUST NOT 创建目录、MUST NOT 打开日志文件、MUST NOT 发起网络请求 |
| 敏感字段 | `ApiKey` / `HttpToken` 字段带 `json:"-"` 与 `toml:"-"`，只能在内存里被 `Redacted` 之外的路径读取 |

## 三、DeepSeek 层

```go
package deepseek

import (
    "context"

    "github.com/LseKit/DeepSeekSearch/internal/domain"
)

// Client 是上游能力的唯一入口。
// 实现者 MUST 保证：单次方法调用至多产生一次上游 HTTP 请求（重试由 Resilience 包裹在外部）。
type Client interface {
    // Search 调用 POST /v1/tools/search。
    // 返回 nil error 时，Results 可能为空切片（上游零结果），调用方 MUST 区分「空结果」与「出错」。
    Search(ctx context.Context, req domain.SearchRequest) (domain.SearchResponse, error)

    // Fetch 调用 POST /v1/tools/fetch。
    // 返回的 Content 是上游原文（含 Markdown 反斜杠转义），反转义由 Tools 层负责。
    Fetch(ctx context.Context, req domain.FetchRequest) (domain.FetchResponse, error)

    // Ping 发 `GET {base_url}/v1/tools/search`，把 HTTP **405** 判定为健康（见 ADR-015）。
    // MUST NOT 计费：405 的空响应体不满足「HTTP 200 且拿到内容」的计费条件（实测确认）。
    // 供 ds_health 与启动自检使用；不校验 API Key 有效性（那需要计费调用）。
    // 返回的 error MUST 携带诊断信息：404 ⇒ base_url 或路径配错；401 ⇒ Key 失效；
    // 网络错误 ⇒ 2998。返回 nil 表示链路健康。
    Ping(ctx context.Context) error
}

// New 构造 Client。cfg 中的 ApiKey 由调用方从 env 注入，本包不读环境变量。
func New(cfg Config) Client

// Config 是 Client 自己的依赖参数，不是全局 Config。
type Config struct {
    BaseUrl   string // 默认 https://api.deepseek.com
    ApiKey    string // 仅内存持有，MUST NOT 出现在任何日志/错误中
    UserAgent string // 为空时由 BuildInfo 在运行时拼装（版本号 MUST NOT 出现在配置文件里）

    // —— 单次尝试的总闸门 ——
    // PerAttempt 是「一次 HTTP 往返」的硬上限，由本包用 context.WithTimeout 执行。
    // 归属说明：Resilience 只管「试几次、间隔多久」，MUST NOT 管单次多久 —— 否则
    // ResponseHeaderTimeout 之后上游慢速滴流 body 就完全没有保护（实测 30s 网关超时）。
    PerAttempt time.Duration // search 默认 12s（实测 0.27~0.71s，留足余量）；fetch 默认 45s（上游 30s 硬超时 + 余量）

    // —— 分层超时（映射到 http.Transport）——
    Dial           time.Duration // DialContext 超时，默认 5s
    TLSHandshake   time.Duration // TLSHandshakeTimeout，默认 5s
    ResponseHeader time.Duration // ResponseHeaderTimeout，默认 15s（fetch 建议 35s）

    MaxResponseBytes int64            // 响应体读取上限，防 OOM。实际读 max+1 以检测溢出
    BuildInfo        domain.BuildInfo // 用于 User-Agent 与日志
}
```

> 🔴 **`PerAttempt` 与三个分层超时的关系**：分层超时保护「连接建立的各阶段」，`PerAttempt` 保护「整次往返（含读 body）」。二者 MUST 同时存在 —— 只有分层超时时，一个每秒滴 1 字节的响应可以无限拖下去。
>
> **校验约束**（`Task-03` 的 `Validate()` MUST 检查）：`PerAttempt ≥ Dial + TLSHandshake + ResponseHeader`。否则分层超时永远轮不到触发，配置成了装饰品。

### 3.1 约定

| 项 | 规定 |
|---|---|
| 超时 | `Config.Timeout` MUST > 上游网关超时（实测 30s），默认 **60s**。理由：上限 30s 会自己掐掉仍在执行的请求，白付一次费 |
| 错误 | MUST 返回 `*domain.UpstreamError`（实现 `error`），MUST NOT 返回裸 `http.Client` 错误或 `url.Error` |
| request_id | 上游错误消息形如 `(request_id: xxx)`，实现 MUST 用 `12-数据契约.md` §1.4 的正则提取并放入 `UpstreamError.RequestId` |
| 敏感信息 | 错误消息 MUST NOT 包含 API Key。实现 MUST 在拼错误前做一次 scrub |
| 空结果 | 上游 200 + `results: []` MUST 返回 `(空响应, nil)`，MUST NOT 当成错误 |
| 不做的事 | 本包 MUST NOT 重试、MUST NOT 限流、MUST NOT 读写缓存。它只负责「一次 HTTP 往返 + 解析」 |

## 四、Resilience 层

```go
// 本层采用「接口根 + 实现子包」：接口、Clock、Config、Reason 与 SystemClock 在
// internal/resilience 根包；构造器与各自专用的参数/诊断类型在同名子包。
// 子包只 import 根包与 domain，根包 MUST NOT import 任何子包，兄弟子包之间 MUST NOT 互相 import。
package resilience

import (
    "context"
    "time"
)

// Clock 是全层可注入的时钟。生产用 SystemClock，测试用 FakeClock。
type Clock interface {
    Now() time.Time
    Sleep(d time.Duration) // MUST 可被 ctx 取消的实现在 Retry 内部使用；本方法仅供后台任务
    // After 返回 d 之后触发一次的 channel，供 Limiter/Retry 做可被 ctx 取消的等待。
    // 没有它，Sleep 无法同时尊重 ctx（会产生无法回收的 goroutine）。
    After(d time.Duration) <-chan time.Time
}

// SystemClock 是 Clock 的生产实现。
func SystemClock() Clock

// Limiter 是按 key 隔离的令牌桶集合。Search 与 Fetch 各占一个桶，互不占用。
type Limiter interface {
    // Wait 阻塞直到取得一枚令牌**与一个在飞名额**，或 ctx 结束 / 等待超时。
    // key 取值固定为 "search" / "fetch"；传入其它 key MUST 返回 error。
    // 🔴 两段等待的规则见 Task-06 §A-01 3.3：先令牌后在飞；两段**共用**一个
    //    maxWait 截止时间（最坏总等待 ≤ maxWait，不是 2×）；拿到令牌但在飞满时
    //    MUST 把令牌还回去；超时的 3000 带 details.stage = "token" | "inflight"。
    Wait(ctx context.Context, key string) error
    // Depth 返回当前排队深度，供错误体携带。
    Depth(key string) int
    // Release 释放在飞名额；Wait 成功返回后调用方 MUST 配对调用。
    // 没有它，Wait 取得的在飞名额永不释放，per-key 配额会在第 N 次调用后永久卡死。
    Release(key string)
}

// Reason 说明「为什么不再重试」（类型名与 Task-06 §A-02 5 的骨架一致）。
// 🔴 它 MUST 存在：没有它，3010 LOC_RETRY_BUDGET 永远无法被返回 ——
//    Should 只回 bool 时，调用方无法区分「重试预算耗尽」与「错误本身不可重试」，
//    而这两者给用户的 hint 完全不同（前者要等窗口滑过去，后者换参数也没用）。
type Reason int

const (
    ReasonOK                Reason = iota // 应当重试
    ReasonDisabled                        // retry.enabled = false
    ReasonAttemptsExhausted               // attempt >= max_attempts
    ReasonNotRetryable                    // CodeRegistry[code].Retryable == false
    ReasonBudgetExhausted                 // 重试预算耗尽 → 调用方 MUST 转成 3010
)

// Retry 决定一次失败是否重试，并计算退避时长。
type Retry interface {
    // Should 返回是否应再试一次，以及不应重试时的原因。attempt 从 1 开始。
    // 🔴 返回 ReasonBudgetExhausted 时调用方 MUST 返回 3010 而不是原始错误，
    //    否则用户看到的是「上游 5xx」，而真实原因是我方主动停止放大。
    Should(err error, attempt int) (bool, Reason)
    // Delay 返回第 attempt 次失败后的等待时长（含抖动）。MUST NOT 返回负数。
    // 🔴 jitter_mode = "full" 时公式是 rand(0, fixed[i] × 2^attempt)，
    //    指数因子 MUST 封顶在 2^10；i = min(attempt-1, len(fixed)-1) 防越界。
    //    见 Task-06 §A-02 第 3.1~3.3 条。
    Delay(attempt int) time.Duration
}

// Budget 是三层硬顶：单次响应字符数 / 时间窗内调用次数 / 日累计调用次数。
type Budget interface {
    // CheckWindow 在发起上游请求前调用。超限返回 *domain.LocalError（3070）。
    CheckWindow(key string) error
    // CheckDaily 在发起上游请求前调用。超限返回 *domain.LocalError（3070）。
    CheckDaily(key string) error
    // Record 在请求成功后调用一次，用于计数。
    Record(key string, upstreamCalls int)
    // TrimChars 截断一段文本到剩余预算，返回截断后文本与是否被截断。
    TrimChars(s string) (string, bool)
    // Reset 清零全部计数（测试用）。
    Reset()
}

// Cache 是持久化键值缓存。阶段一唯一实现是 SQLite 版本，理由见 ADR-006。
type Cache interface {
    // Get 命中返回 (值, true)。过期视为未命中并删除。
    Get(ctx context.Context, key string) ([]byte, bool, error)
    // Put 写入并设置 TTL。ttl <= 0 表示立即过期（等价于不缓存）。
    Put(ctx context.Context, key string, val []byte, ttl time.Duration) error
    // Stats 返回当前条目数与总字节数，供日志与 /healthz 使用。
    Stats() (entries int, bytes int64, degraded bool)
    // Prune 主动清理过期条目。启动时一次 + 每 cache.prune_interval_s（默认 300s）一次。
    Prune(ctx context.Context) (removed int, err error)
    // Close 刷盘并关闭连接。
    Close() error
}

// Singleflight 保证「同一 key 在同一时刻只有一次上游请求」，跨 goroutine 与跨进程同时生效。
// 内存层用 map+mutex，跨进程层用 SQLite inflight 表。
type Singleflight interface {
    // Do 执行 fn，或等待他人执行完共享结果。
    // 返回 shared=true 表示本次没有真正执行 fn（结果来自他人）。
    // 等待超过 waitMs 返回 *domain.LocalError（3075）。
    //
    // 🔴 commit MUST 是 Do 的参数，不能由调用方在 Do 返回后再自己 Put：
    //    owner 的顺序必须是 fn 成功 → commit(val) 成功 → 才 DELETE 租约。
    //    否则「租约消失」与「值可读」之间存在窗口，跨进程等待者在这个窗口里
    //    既读不到值也看不到租约，只能重新发起上游请求 ⇒ 同一次调用**被计费两次**。
    //    时间线证明见 Task-07 §A-02 3.1。
    // commit 返回 error 时：记 warn.cache_commit_failed、**仍然删租约**、把 fn 的结果
    //    照常返回给进程内等待者（跨进程等待者会走 3075，这是可接受的降级）。
    Do(ctx context.Context, key string, waitMs int,
        fn func(context.Context) ([]byte, error),
        commit func(context.Context, []byte) error) (val []byte, shared bool, err error)

    // ReleaseAll 清理属于 ownerID 的全部租约。MUST 在进程退出前调用，
    // 位置在 cmd 关闭序列的 cancel() 之后、cache.Close() 之前。
    // 🔴 ownerID 传空串表示「本实例」：owner 由 NewSingleflight 内部按
    // hostname:pid:startupNano 生成，不暴露给装配层（否则 cmd 复制一份算法必然漂移）。
    ReleaseAll(ctx context.Context, ownerID string) (released int, err error)
}

// Circuit 是按 key 隔离的熔断器。
type Circuit interface {
```

| 项 | 规定 |

### 6.1 中间件硬规则（实测踩坑，必读）

> 任何包装 `http.ResponseWriter` 的中间件（日志、CORS、鉴权、限流）MUST 显式实现 `http.Flusher` 接口与 `Unwrap() http.ResponseWriter` 方法。

理由：`http.ResponseWriter` **接口本身不含 `Flush`**，嵌入接口不会提升方法。只包一层 `statusWriter` 会导致流式响应永远不 flush —— 实测表现为 `curl` 3 秒收到 0 字节、SDK 客户端连接 hang 满 3 分钟，且**没有任何错误日志**。

参考实现（MUST 逐字使用）：

```go
type statusWriter struct {
    http.ResponseWriter
    code int
    n    int64
}

func (s *statusWriter) WriteHeader(c int) { s.code = c; s.ResponseWriter.WriteHeader(c) }

func (s *statusWriter) Write(p []byte) (int, error) {
    n, err := s.ResponseWriter.Write(p)
    s.n += int64(n)
    return n, err
}

func (s *statusWriter) Flush() {
    if f, ok := s.ResponseWriter.(http.Flusher); ok {
        f.Flush()
    }
}

func (s *statusWriter) Unwrap() http.ResponseWriter { return s.ResponseWriter }
```

### 6.2 streamable-http 中间件链（顺序固定，MUST NOT 调换）

```
请求 →  recover(panic→500)
      →  accessLog(记录 status/bytes/耗时，用 statusWriter)
      →  securityHeaders(X-Content-Type-Options: nosniff)
      →  healthz 分流（命中 healthz_path 直接返回，不鉴权）
      →  pathGuard（只放行配置的 MCP 路径）
      →  admission（入口并发闸门，超限 429/3094）
      →  crossOrigin（http.NewCrossOriginProtection）      🔴 在 hostGuard/authGuard 之外
      →  hostGuard（allow_non_local_host=false 时校验 Host 为回环，否则 403/3093）
      →  authGuard（auth_enabled=true 时校验 Bearer，否则 401/3091）
      →  bodyLimit（MaxBytesReader = max_request_body_bytes）
      →  mcpHandler
```

> 🔴 **`crossOrigin` 的位置改过（原在 `authGuard` 之内），完整裁决与三条后果见 `15-协议契约` §六之二，实现归 `Task-11` A-02。**
> 一句话版本：preflight 的 `OPTIONS` **不携带 `Authorization`**，`crossOrigin` 在 `authGuard` 之内 ⇒ preflight 先吃 `401`（`3091`），`Access-Control-Allow-*` 头永远发不出去 ⇒ 浏览器判 CORS 失败，真正的 `POST` 根本不会发出。即 `auth_enabled=true` 时**任何浏览器端 MCP 客户端都不可用**。
> 顺序由 `Task-11` A-02 的 `TestMiddlewareOrder` 强制（断言 `chain()` 的 `middlewareNames` 序列），MUST NOT 只靠 review 把关。

## 七、装配顺序（Cmd 的责任，MUST 按此顺序）

```
 1. 解析 flag：-config / -env / -transport / -version / -check
 2. -version → 打印 BuildInfo → exit 0（此时不读配置、不建目录）
 3. domain 包初始化 mustLoadCST8()           → 失败 panic（tzdata 已随二进制编入）
 4. config.Load(路径...)                     → 失败 exit(1)，打印字段路径+行号
 5. -check   → 校验通过后打印一行摘要（transport/host/port/cache） → exit 0
 6. logger   := newLogger(cfg.Log)           → 含轮转；失败 exit(1)
 7. cacheStore := cache.NewSqliteCache(...) → 失败按 cfg.Cache.DegradedOk 决定降级或退出
 8. limiter    := ratelimit.NewLimiter(...)
 9. budget     := budget.NewBudget(...)
10. retry      := retry.NewRetry(...)
11. circuit    := circuit.NewCircuit(...)
12. sflight    := cache.NewSingleflight(cacheStore, clock)
13. client   := deepseek.New(...)            → 校验 base_url；ApiKey 由 config 阶段检查
14. srv      := mcp.NewServer(impl, opts)    → 含 SetCacheable(ttlMs, scope)
15. tools.RegisterAll(srv, deps)             → 含 Resources
16. handler  := transport.BuildWithCache(..., cacheStore)
17. 注册 SIGINT/SIGTERM → cancel ctx → cache.Close() → logger.Close()
18. 打印 app.ready（transport / 地址 / config_sha256）
19. handler.Serve(ctx, srv)                  → 返回即退出
```

**MUST NOT 在装配阶段发起任何上游网络请求。** 启动必须能在离线环境完成。

**唯一例外**：`-check` 之外的启动路径中，若 `cfg.Upstream.SelfTestOnStart=true`，允许在 5 秒超时内做一次 `Client.Ping`（不计费），失败只记 WARN 不阻止启动。
