## 二、Go 官方规范（MUST 逐条遵守）

来源：<https://go.dev/doc/effective_go> + <https://google.github.io/styleguide/go/>。以下十条是**最容易被 AI 写错**的，因此单列。

| # | 规则 | 反例 → 正例 |
|:-:|---|---|
| G1 | **命名用 MixedCaps，不用下划线** | `api_key` → `apiKey`；`MAX_RETRY` → `maxRetry` |
| G2 | **首字母缩写全大写或全小写，不混写** | `urlPath` → `urlPath` ✅ / `UrlPath` ❌ / `URLPath` ✅（导出）/ `httpUrl` → `httpURL` |
| G3 | **receiver 名统一且短**（1~2 字母，取类型首字母），同一类型全部方法 MUST 同名 | `func (this *Client)` → `func (c *Client)` |
| G4 | **`ctx context.Context` MUST 是第一个参数**，MUST NOT 存进 struct | `func (c *Client) Search(req, ctx)` ❌ |
| G5 | **错误字符串小写、无标点结尾** | `"Failed to fetch URL."` ❌ → `"failed to fetch url"` ✅ |
| G6 | **正常错误用 `error` 返回，不用 panic** | `panic("config invalid")` ❌ → `return fmt.Errorf(...)` ✅ |
| G7 | **错误必须 wrap，且 `%w` 只能有一个** | `fmt.Errorf("config: %w: %w", a, b)` ❌ → `errors.Join(a, b)` ✅ |
| G8 | **interface 定义在**使用方**包，不在实现方包** | `deepseek` 包里定义 `Client` ❌ → 例外：本项目的 `Client` 由 `tools` 依赖，故定义在 `deepseek` 包并在 `10-包依赖矩阵` 里登记为例外 |
| G9 | **`init()` MUST NOT 使用**（除 `_test.go`） | 依赖注入在 `Cmd` 里显式做 |
| G10 | **struct tag 用 `json`，MUST NOT 用 `map[string]any` 承载协议数据** | 实测上游**静默忽略**未知字段，用 map 打错键名不会报错 |

### 2.1 本项目追加的三条

| # | 规则 | 理由 |
|:-:|---|---|
| G11 | **时间 MUST 从注入的 `Clock` 取，MUST NOT 直接 `time.Now()`** | 直接调会让「跨日切分日志」「TTL 过期」这类测试无法确定性复现 |
| G12 | **`[]byte` 转 `string` 前 MUST 考虑拷贝成本**；大响应体走 `bytes.Buffer` 或 `io.Reader` | Fetch 实测单次正文最大 439,285 字节，无脑 `string(b)` 会产生大量临时对象 |
| G13 | **`defer` 里的错误 MUST 显式处理**，命名返回值 + `defer func() { err = errors.Join(err, f.Close()) }()` | `defer f.Close()` 静默吞掉刷盘错误，日志文件最后几行会丢 |

## 三、规模红线（F-S1 ~ F-S6）

> 来源：`McpMesh` 项目宪法实测校准后的阈值。**每条都由脚本检查，不靠自觉。**

| 编号 | 红线 | 统计口径 | 超限处理 |
|:-:|---|---|---|
| **F-S1** | 单文件 ≤ **600** 行 | 含空行与注释（物理行数） | 按职责拆分文件，MUST NOT 靠删注释过关 |
| **F-S2** | 单函数 ≤ **50** 行 | **不含**注释与空行 | 提取子函数；若提取后参数 > 5 个，说明该拆结构体 |
| **F-S3** | 圈复杂度 ≤ **10** | `if` / `for` / `case` / `&&` / `\|\|` 各 +1 | 用查表法替代分支链；`switch` 拆成策略函数 |
| **F-S4** | 嵌套深度 ≤ **3** | `if/for/switch/func literal` 层数 | 卫语句提前 return |
| **F-S5** | 单包 ≤ **3000** 行、≤ **10** 个文件、≤ **20** 个导出符号 | 非测试文件 | 拆包；拆包必须同步更新 `10-包依赖矩阵` |
| **F-S6** | 豁免必须登记 | 见 §3.2 | 未登记的豁免 = 违规 |

### 3.1 自查命令

🔴 **每条红线由谁强制，MUST 先看 `Engineering/22-架构守护规则.md` §三 的分工表**，本节只给「本地想快速看一眼」的命令。原文这里写「F-S2 / F-S3 / F-S4 用 `gocyclo -over 10` 找超限函数」是**错的**：`gocyclo` 算的是**圈复杂度**，只能覆盖 F-S3；它既数不出函数行数（F-S2），也数不出嵌套深度（F-S4）。照它自查会得到「gocyclo 无输出 ⇒ 三条都过了」的假绿。

```bash
# F-S1 单文件 ≤600 行（强制方：Scripts/CheckSize.sh）
find internal cmd -name '*.go' ! -name '*_test.go' -print0 \
  | xargs -0 wc -l | sort -rn | head -20

# F-S3 圈复杂度 ≤10（强制方：Scripts/CheckSize.sh 调 gocyclo 二进制）
gocyclo -over 10 ./internal/...

# 🔴 F-S2 函数 ≤50 行 与 F-S4 嵌套 ≤3 层：
#    强制方是 internal/arch_test.go 的 TestFunctionLength / TestNestingDepth（go/ast），
#    **没有任何命令行工具能替代** —— 本地自查就跑这两个测试：
go test ./internal/ -run 'TestFunctionLength|TestNestingDepth' -v

# F-S5 单包 ≤3000 行 / ≤10 文件（强制方：Scripts/CheckSize.sh + TestSizeLimits）
# 🔴 原写法 `cat $d*.go | grep -v _test` 是错的：grep -v 过滤的是**行内容**里含
#    "_test" 的行，不是文件名 —— 测试文件的代码行照样被算进去，行数虚高。
for d in internal/*/; do
  files=$(find "$d" -maxdepth 1 -name '*.go' ! -name '*_test.go')
  [ -z "$files" ] && continue
  echo "$d $(cat $files | wc -l) 行 $(echo "$files" | wc -l) 文件"
done

# 一次跑全（与 CI / make check 同口径）
bash Scripts/CheckSize.sh . docs     # 🔴 MUST 两个参数
go test ./internal/ -run 'TestSizeLimits|TestFunctionLength|TestNestingDepth'
```

> 🔴 **`CheckSize.sh` MUST 传两个参数**（`<代码根> <文档根>`）。文档根是仓库内 `docs`；路径写错会 **豁免台账加载不到** ⇒ 已登记的 `internal/domain`（F-S5）与 `domain/time.go`（G6）会直接判违规。

### 3.2 F-S6 豁免台账

位置：`docs/Engineering/豁免台账.md`。格式：

| 文件 | 违反项 | 实测值 | 不拆的理由 | 复核日期 |

## 四、注释规范（中文，Go doc 形式）

### 4.1 形式（MUST）

```go
// Search 调用 POST /v1/tools/search 并返回解析后的结果。
//
// 上游对 query 长度按 rune 计，1~128；超长直接 400，不发计费请求。
func (c *client) Search(ctx context.Context, req domain.SearchRequest) (domain.SearchResponse, error) {
```

| 规则 | 说明 |
|---|---|
| 以**标识符名开头** | `// Search 调用...` ✅ / `// 调用搜索接口` ❌ |
| 以**句号结尾** | Go 官方 `golint` 惯例 |
| 空行分隔摘要与正文 | 第一行是摘要（`go doc` 列表里显示的那句） |
| 导出符号 **MUST** 有注释 | `revive: exported` 强制 |
| 包 **MUST** 有包注释 | `revive: package-comments` 强制，写在 `doc.go` 或首个文件顶部 |

### 4.2 内容（MUST 写「为什么」，MUST NOT 写「做什么」）

```go
// ❌ 错：说明书式注释。读者看代码就知道在干什么。
// 遍历 results，对每个元素取 url 字段
for _, r := range results {

// ✅ 对：写代码看不出来的东西 —— 为什么这样、踩过什么坑、哪条实测数据支撑这个决定。
// 上游把 403/404/500/域名不存在/内网 IP/二进制内容全部塌缩成同一个 404，
// 所以这里无法按状态码分类，只能把 7 种成因写进 hint 交给调用方自己判断。
```

**只有以下四类内容值得写注释**：

| 类型 | 例子 |
|---|---|
| 为什么这样做 | 「不用 `time.FixedZone`，因为它不带时区名，日志里显示 `+0800` 不可读」 |
| 踩过的坑 | 「包装 ResponseWriter 必须实现 Flush，否则流式响应静默卡死」 |
| 实测数据 | 「实测 fetch 正文最大 439,285 字节、`count=50+need_content` 的 search 响应 636KB，所以 ReadLimit 设 8MB」<br>⚠️ 原例写的是「实测单次响应最大 636KB」—— 那条泛化断言已被 23 号 §4.6/§4.7 推翻（真正的量级证据是上面两个具体样本）。示例里的数据也必须是真的，否则这条规则就是在教人写另一种不靠谱的注释 |
| 反直觉的取舍 | 「这里故意不重试 404：上游把 403 也塌缩成 404，重试只会重复付费」 |

### 4.3 禁止的注释

| 禁止 | 例子 |
|---|---|
| 复述代码 | `// i 自增` |
| `TODO` 不带日期与人 | `// TODO 优化这里` ❌ → `// TODO(2026-11-01, 小逸): 待 DEBT-002 实现批量抓取` |
| 注释掉的死代码 | 用 git 记历史，不留残骸 |
| 英文注释 | 本项目全中文（标识符除外） |
| 表情符号 / ASCII 艺术 | 日志与终端编码不一致时会乱码 |

### 4.4 文件头与作者署名

每个 `.go` 文件 MUST 以文件头注释开头，字段与顺序固定（与 `Contract/19-AGENTS.md全文.md` §5.5 同源）：

```go
// 文件名: dedupe.go
// 用途: 搜索结果三层去重（URL hash / 转载标题 / 域名配额），输出保持 rerank_score 降序。
// 创建日期: 2026-10-20
// 作者: 小逸
// 项目: DeepSeekSearch <https://github.com/LseKit/DeepSeekSearch>
package domain
```

| 字段 | 规定 |
|---|---|
| `文件名` | 与磁盘文件名一致（含扩展名） |
| `用途` | 一句话说清这个文件负责什么，MUST NOT 同义反复 |
| `创建日期` | `YYYY-MM-DD`，新建时定下，之后修改不改 |
| `作者` | 恒为 **`小逸`**。MUST NOT 出现 AI / 助手 / 模型 / 生成工具名字，MUST NOT 有第二作者 |
| `项目` | 恒为 `DeepSeekSearch <https://github.com/LseKit/DeepSeekSearch>` |

`.sh` 文件的头注释写在 shebang **之后**。

**包注释只写在 `doc.go`**（每包一个）。其它文件如果也写包注释，`go doc` 会显示多份重复的包文档，且改一处忘一处。

```go
// 文件名: doc.go
// 用途: 定义全项目共用的类型、错误码与纯函数，并提供包级文档。
// 创建日期: 2026-10-20
// 作者: 小逸
// 项目: DeepSeekSearch <https://github.com/LseKit/DeepSeekSearch>

// Package domain 定义全项目共用的类型、错误码与纯函数。
//
// 本包 MUST NOT 导入本项目其它包，也 MUST NOT 做任何 IO。
package domain
```

> 这条规则是 `revive: package-comments` 与「文件头」两条要求的**同时满足方式**：包注释在 `doc.go`，文件头在每个文件。

## 六、日志规范

| 规则 | 说明 |
|---|---|
| MUST 用 `*slog.Logger` | MUST NOT 用 `log.Printf` / `fmt.Println` |
| MUST 结构化 | `logger.Info("call.end", "tool", "ds_search", "ms", 812)` ✅ / `logger.Info("search done in 812ms")` ❌ |
| 事件名 | 用小写点分：`app.start` / `call.begin` / `call.upstream` / `err` |
| 字段名 | 全小写下划线：`call_id` / `config_sha256` / `billed` |
| 敏感值 | API Key / Bearer token MUST NOT 出现在任何日志。`Redacted()` 后再打 |
| 级别 | `DEBUG` 只在排查时开；`INFO` 每次调用 ≤ 3 行；`WARN` 可降级问题；`ERROR` 需要人看 |
| stdout | 🔴 **stdio 传输下 stdout 只能出协议帧**。日志 MUST 走 stderr 或文件 |

完整事件表（🔴 28 个）在 `Tasks/Task-04-日志与轮转.md` A-02；字段规则在 `Contract/13-配置契约` §3.11。

## 七、禁止事项清单（code review 逐条对照）

| # | 禁止 | 理由 |
|:-:|---|---|
| P1 | `panic` 用于正常错误路径 | 一个 panic 会带走整个进程，stdio 下客户端直接断连 |
| P2 | 包级可变 `var`（除哨兵错误、正则、常量表） | 破坏可测试性，多 goroutine 下是数据竞争 |
| P3 | `init()` 做 IO | 无法控制执行时机，测试里无法替换 |
| P4 | 直接 `time.Now()` | 见 G11 |
| P5 | 无 `ctx` 的 `http.NewRequest` | 调用无法取消 |
| P6 | `defer resp.Body.Close()` 前不检查 `err` | nil panic |
| P7 | `map[string]any` 承载协议数据 | 见 G10 |
| P8 | 包装 `http.ResponseWriter` 但不实现 `Flush` + `Unwrap` | 实测导致流式响应静默卡死 3 分钟，零错误日志 |
| P9 | 在 `internal/domain` 里 import 本项目其它包 | 破坏依赖 DAG，形成循环 |
| P10 | 靠 `strings.Contains(err.Error(), ...)` 判断错误类型 | MUST 用 `errors.Is` / `errors.As` |
| P11 | 把 `APIKey` 拼进任何 `fmt.Errorf` | 泄漏到日志 |
| P12 | 未注册的 F-S 豁免 | 见 §3.2 |
| P13 | 在 `ds_fetch` 里对上游正文做 HTML 清洗 | 上游给的已是 Markdown；自己清洗会破坏代码块与表格 |
| P14 | 用字节切片处理正文长度 | 中文 1 字 3 字节，`s[0:8000]` 会切出乱码。MUST 用 `SliceByRune` |
| P15 | 静默忽略配置里的未知键 | 上游犯过的错，MUST NOT 重犯 |
