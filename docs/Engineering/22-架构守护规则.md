                    ← 空行
package internal_test

三处（本文件、`19-AGENTS.md全文` H11、`91-验收总表` D8）MUST 一致。**代价**：`package` 前有空行 ⇒ 该文件没有 package doc comment，对测试文件无影响。

> 🔴 **完整可运行的实现归 `Tasks/Task-11-Transport与架构守护.md` A-03 §5**（六个测试同放一个 `internal/arch_test.go`）。本节只给**语义与白名单**，两者冲突时以本节的 import 清单为准 —— 因为它直接决定能不能编译（Go 的未使用 import 是**编译错误**）。

## 三、AR-4：规模红线实现

> **分工（此前含糊，导致 F-S2 / F-S4 无人强制）**
>
> | 红线 | 由谁强制 | 为什么 |
> |---|---|---|
> | F-S1 单文件 ≤600 行 | `CheckSize.sh` | `wc -l` 足够 |
> | F-S3 圈复杂度 ≤10 | `CheckSize.sh`（调 `gocyclo`） | 现成工具 |

> 🔴 原设计声称「F-S1~F-S5 由 CheckSize.sh + TestSizeLimits 强制」，但脚本全文只实现了 F-S1/F-S3/F-S5，而 `20-编码规范` §1.1 又明确关掉了 `funlen`/`gocognit`/`gocyclo` 这三个能覆盖 F-S2 的 linter ⇒ **F-S2 与 F-S4 处于「写在文档里但无人强制」状态**，恰好违反本文 §一 的核心主张（「写在文档里的约束是愿望」）。现按上表补齐。

### 3.1 `Scripts/CheckSize.sh`

```bash
#!/usr/bin/env bash
# 文件名: CheckSize.sh
# 用途: 检查 F-S1 / F-S3 / F-S5 规模红线，违规时非零退出。
#       F-S2 / F-S4 由 internal/arch_test.go 的 TestSizeLimits 用 go/ast 检查。
#       豁免项从 Doc/Engineering/豁免台账.md 的 ```exempt 块读取。
# 创建日期: 2026-10-20
# 作者: 小逸
# 项目: DeepSeekSearch <https://github.com/LseKit/DeepSeekSearch>
# 用法: CheckSize.sh <代码根> <文档根>
#   例: CheckSize.sh .        ../Doc     (在 GitHubSrc/ 下)
#       CheckSize.sh GitHubSrc Doc       (在部署根下)
set -uo pipefail

SRC_ROOT="${1:-GitHubSrc}"
DOC_ROOT="${2:-Doc}"
EXEMPT_FILE="$DOC_ROOT/Engineering/豁免台账.md"
FAIL=0

# ---------------------------------------------------------------------------
# 读取豁免台账：解析 ```exempt 块，格式为五段（空格分隔，理由可含空格故用引号）
#   <文件相对路径>  <红线代号>  <实测值>  "<理由>"  <复核日期 YYYY-MM-DD>
# 红线代号填 "—" 的条目（如 G6 panic 例外）不是规模豁免，直接跳过。
# ---------------------------------------------------------------------------
declare -A EXEMPT=()
EXEMPT_N=0
if [ -f "$EXEMPT_FILE" ]; then
  while IFS= read -r line; do
    # 跳过空行与红线代号为 "—" 的非规模类条目
    [ -z "${line// }" ] && continue
    rule=$(awk '{print $2}' <<<"$line")
    [ "$rule" = "—" ] || [ "$rule" = "-" ] && continue
    file=$(awk '{print $1}' <<<"$line")
    EXEMPT["$file|$rule"]=1
    EXEMPT_N=$((EXEMPT_N + 1))
  done < <(awk '/^```exempt$/{f=1;next} /^```$/{f=0} f' "$EXEMPT_FILE")
else
  echo "⚠️  豁免台账不存在: $EXEMPT_FILE（本次不放行任何豁免）"
fi
echo "已加载规模豁免 $EXEMPT_N 条"

exempted() { [ -n "${EXEMPT["$1|$2"]:-}" ]; }

# ---------------------------------------------------------------------------
# F-S1 单文件 ≤600 物理行（含空行与注释，口径见 20-编码规范 §三）
# ---------------------------------------------------------------------------
while IFS= read -r f; do
  rel="${f#"$SRC_ROOT"/}"
  n=$(wc -l < "$f")
  if [ "$n" -gt 600 ]; then
    if exempted "$rel" F-S1; then
      echo "F-S1 豁免: $rel 有 $n 行（台账放行）"
    else
      echo "F-S1 违规: $rel 有 $n 行 (上限 600)"
      FAIL=1
    fi
  fi
done < <(find "$SRC_ROOT/internal" "$SRC_ROOT/cmd" -name '*.go' ! -name '*_test.go' 2>/dev/null)

# ---------------------------------------------------------------------------
# F-S5 单包 ≤3000 行 / ≤10 文件 / ≤20 导出符号
# 🔴 三处口径修正（原实现全错）：
#   ① 行数 MUST 排除 _test.go —— 原来用 `cat "$d"*.go` 的 glob 把测试文件算进去了，
#      而同一段的文件数统计却用 find 排除了测试，两者口径不一致
#   ② 行数 MUST 含注释与空行 —— 原来的 `grep -v '^//'` 与 F-S1 的「物理行」口径矛盾，
#      且剔不掉行尾注释与块注释
#   ③ 导出符号 MUST 含方法与 const/var 块内成员 —— 原来的
#      `^(func|type|var|const) [A-Z]` 漏掉 `func (c *Client) Foo()` 与
#      `const ( CodeXxx = ... )`，系统性少数，「≤20」形同放宽
# ---------------------------------------------------------------------------
for d in "$SRC_ROOT"/internal/*/; do
  [ -d "$d" ] || continue
  pkg=$(basename "$d")
  lines=$(find "$d" -maxdepth 1 -name '*.go' ! -name '*_test.go' -print0 2>/dev/null \
            | xargs -0 cat 2>/dev/null | wc -l)
  files=$(find "$d" -maxdepth 1 -name '*.go' ! -name '*_test.go' 2>/dev/null | wc -l)
  # 近似统计：顶层声明 + 方法 + 块内导出成员。精确值由 TestSizeLimits 的 go/ast 复核。
  exports=$(grep -rhoP '^(func\s+(\([^)]*\)\s*)?[A-Z]\w*|type\s+[A-Z]\w*|var\s+[A-Z]\w*|const\s+[A-Z]\w*)' \
              "$d" --include='*.go' --exclude='*_test.go' 2>/dev/null \
            | grep -oP '[A-Z]\w*$' | sort -u | wc -l)
  exports_block=$(grep -rhoP '^\t[A-Z]\w*(\s|=)' "$d" --include='*.go' --exclude='*_test.go' 2>/dev/null \
                    | grep -oP '[A-Z]\w*' | sort -u | wc -l)
  exports=$(( exports > exports_block ? exports : exports_block ))

  if [ "$lines" -gt 3000 ]; then
    exempted "$pkg" F-S5 && echo "F-S5 豁免: $pkg 行数 $lines" \
      || { echo "F-S5 行数违规: $pkg $lines (上限 3000)"; FAIL=1; }
  fi
  if [ "$files" -gt 10 ]; then
    exempted "$pkg" F-S5 && echo "F-S5 豁免: $pkg 文件数 $files" \
      || { echo "F-S5 文件违规: $pkg $files (上限 10)"; FAIL=1; }
  fi
  if [ "$exports" -gt 20 ]; then
    exempted "$pkg" F-S5 && echo "F-S5 豁免: $pkg 导出符号 $exports" \
      || { echo "F-S5 导出违规: $pkg $exports (上限 20)"; FAIL=1; }
  fi
done

# ---------------------------------------------------------------------------
# F-S3 圈复杂度 ≤10
# 🔴 判据修正：gocyclo 无论有没有超限函数都 **退出 0**（它只打印）。
#   原写法 `gocyclo ... && { FAIL=1; } || true` 在装了 gocyclo 时 && 分支必然执行
#   ⇒ FAIL 恒为 1 ⇒ CI 永远红；若被「顺手修」成 `|| FAIL=1` 则恒绿。两种都错。
#   正确判据是 **输出是否非空**。
# ---------------------------------------------------------------------------
if command -v gocyclo >/dev/null 2>&1; then
  cyclo_out=$(gocyclo -over 10 "$SRC_ROOT/internal" "$SRC_ROOT/cmd" 2>/dev/null)
  if [ -n "$cyclo_out" ]; then
    echo "F-S3 违规: 存在复杂度 >10 的函数"
    echo "$cyclo_out"
    FAIL=1
  fi
else
  echo "⚠️  gocyclo 未安装，F-S3 未检查（开发机安装方式见 90-Qoder执行手册 §二）"
fi

if [ "$FAIL" -eq 0 ]; then
  echo "✅ 规模红线全部通过（F-S1/F-S3/F-S5；F-S2/F-S4 见 TestSizeLimits）"
fi
exit "$FAIL"
```

### 3.4 存量规模基线（ADR-017：只减不增）

Task-11 A-03 首次把 F-S1~F-S5 接进自动化时，实测存量代码有 **29 处**超限（F-S2 5 个函数、F-S3 20 个函数、F-S5 4 个包；F-S4 的 1 处已当场拆卫语句修复）。逐条豁免会违反台账 E5（每个窗口 ≤3 条），全面重构会改动 `Contract/11-接口契约.md` 的冻结导出面。裁决见 `Decisions/ADR.md` ADR-017：**冻结存量、只减不增**。

**基线文件**：`GitHubSrc/Scripts/size-baseline.json`（随代码提交，路径固定，MUST NOT 放到 `docs/` 或临时目录）。

**判定规则**：

1. 基线里**存在**的 key：当前值 > 基线值 ⇒ FAIL；当前值 ≤ 基线值 ⇒ PASS（自然下降允许）。
2. 基线里**不存在**的 key：按 F-S1~F-S5 原阈值判定，超标 ⇒ FAIL。
3. 基线只允许**减小或删除**。任何把 `value` / `exports` / `files` / `lines` 调大的改动 MUST 被拒绝；新增条目 MUST NOT 出现。
4. 新代码 MUST 从第一天起达标，MUST NOT 往基线里加行。
5. `DEBT-010` 清零 = 删除基线文件且 `make size` + 六个守护测试无豁免通过。

**JSON 结构**（`schema=1`）：

```json
{
  "schema": 1,
  "frozen_at": "2026-10-21",
  "f_s1_file_lines": {"<文件相对路径>": {"value": 601, "limit": 600, "phase": 1, "reason": "...", "remediation": "..."}},
  "f_s2_function_lines": {"<包>/<文件>:<函数>": {"value": 68, "limit": 50, "phase": 1, "reason": "...", "remediation": "..."}},
  "f_s3_cyclomatic": {"<包>/<文件>:<函数>": {"value": 20, "limit": 10, "phase": 1, "reason": "...", "remediation": "..."}},
  "f_s4_nesting": {"<包>/<文件>:<函数>": {"value": 4, "limit": 3, "phase": 1, "reason": "...", "remediation": "..."}},
  "f_s5_package": {"internal/x": {"files": 12, "lines": 2987, "exports": 11, "limits": {"files": 10, "lines": 3000, "exports": 20}, "phase": 1, "reason": "...", "remediation": "..."}}
}
```

`reason` MUST 非空；`remediation` 写可执行的拆解方向；`phase` 固定 1（阶段一冻结）。

**分工**：F-S1 / F-S3 / F-S5 由 `Scripts/CheckSize.sh` 执行（F-S5 的导出数用 `Scripts/exportcount.go` 精确统计，MUST NOT 把 struct 字段算入）；F-S2 / F-S4 由 `internal/arch_test.go` 执行。两者读**同一份**基线。

**为什么不用豁免台账承担**：台账 E5 限「每个窗口新增 ≤3 条」，而存量超限有 29 处；把 29 条塞进豁免等于废掉 E5。分工：豁免 = **单条不可拆**的静态例外（如 domain 的 42 个错误码常量）；基线 = **批量存量债**，有统一退出条件（DEBT-010）。

## 八、这套规则解决了什么（写给未来的自己）

| 没有这套规则 | 有这套规则 |
|---|---|
| 「高内聚低耦合」是口号，AI 每次实现的理解都不同 | 白名单写在代码里，AI 想违规就编译不过测试 |
| 文件越写越长，直到没人敢改 | 超 600 行测试红，逼你当场拆 |
| `domain` 慢慢 import 了 `config`，然后 `config` 又 import 了 `deepseek` | 依赖环检测直接红 |
| 工具名从 `ds_search` 变成 `search`，缓存全击穿 | `TestToolNames` 写死了 `want` 列表 |
| 文档说 42 个错误码，代码里有 42 个 | 条数比对红 |
| 三个月后没人知道当初为什么这么分层 | ADR 有记录，改规则必须走 ADR |

**这套规则的成本**：首次落地约 300 行测试与脚本（Task-11）。**收益**：之后每一次改动都有护栏。
