# 21 · 测试规范

> **文件路径**：`/mcp/DeepSeekSearch/Doc/Engineering/21-测试规范.md`
> **用途**：测试怎么写、写在哪、覆盖率门槛、什么算「测过了」的唯一真源。
> **创建日期**：2026-10-20
> **状态**：已冻结
> **原则**：**没有断言输出值的测试不算测试。** `if err != nil { t.Fatal(err) }` 之后没有 `if got != want` 的，一律视为无效测试。

## 一、测试分层模型（L1 / L2 / L3a / L3b）

🔴 **原「L3 = 真实上游 + 真实 API Key」的定义与「协议测试 P1~P26 属 L3（httptest）」自相矛盾**：`httptest` 是**本地假上游**，不需要 Key、不计费，按原定义应属 L1/L2。这个 build tag 归属混乱只有两种结局，都是事故：协议测试被打上 `integration` tag ⇒ 日常 `make test` **静默不跑**（覆盖率虚低、P 断言形同失效）；或不打 tag 却连真实上游 ⇒ **违反 T1「不计费」铁律**。**裁决：拆成 L3a / L3b 两层**，本文所有「L3」MUST 按下表归属。

| 层 | 名字 | 在哪 | 依赖 | 占比 | 触发 |
|:-:|---|---|---|:-:|---|
| **L1** | 单元测试 | `*_test.go`，与源码同目录 | **零外部依赖**（无网络、无文件、无 SQLite 落盘） | ~88% | 每次 `go test` |
| **L2** | 契约/黄金测试 | `*_test.go` + 包内 `testdata/`（`.json` + 同名 `.meta`、`.toml`） | 有固定输入输出文件 | ~8% | 每次 `go test` |
| **L3a** | 协议/端到端测试（**不计费**） | `*_test.go`（进程内起 server + `httptest` 假上游 + stdio 管道） | **本地假上游，无 API Key、零计费** | ~4% | 每次 `go test`（随 `make test` 跑，**不打 tag**） |
| **L3b** | 真实上游集成测试（**计费**） | `*_integration_test.go`，首行 `//go:build integration` | **真实上游 + 真实 API Key** | —（人工低频触发，不计入日常占比） | 显式 `make test-integration` |

### 1.1 铁律

| # | 规则 |
|:-:|---|
| T1 | `go test ./...`（含 `make test` / `make test-race`）MUST **不产生任何计费调用**。L3b 全部靠 `integration` build tag 隔离；L3a 只用本地 `httptest` 假上游，无 Key、不计费，随日常测试跑 |
| T2 | L1 MUST NOT 访问网络、MUST NOT 写项目目录以外的文件 |
| T3 | 测试 MUST NOT 依赖执行顺序，MUST 能单独 `go test -run TestXxx` 通过 |
| T4 | 时间相关测试 MUST 用 `resilience.Clock` 的假实现，MUST NOT 用 `time.Sleep` 等真实时间 |
| T5 | 每个 `exported` 函数 MUST 有 ≥1 个 `Test<函数名>`（或 `Test<类型>_<方法名>`） |
| T6 | 覆盖率不足时 MUST 补测试，MUST NOT 用 `//nolint` 或删断言凑数 |
| T7 | 🔴 **L3a 文件 MUST NOT 打 `//go:build integration`** —— 打了就在日常 `make test` 里静默不跑，协议断言（P1~P26 的可 httptest 部分）全部失效且无人发现。**L3b 文件 MUST 首行打 `//go:build integration`** —— 漏打就等于每次 `go test` 都花真钱（违反 T1） |

## 二、命名规则（MUST）

```go
// 被测算子的名字原样放在 Test 后面，用下划线分隔方法名。
func TestNormalizeUrl(t *testing.T)                  // 函数 NormalizeUrl
func TestSqliteCache_Get(t *testing.T)               // 方法 (*sqliteCache).Get
func TestBuildQuery_WithSiteOperator(t *testing.T)   // 具体场景
func TestSplitSections_NoHeadings(t *testing.T)      // 边界

// 子测试用 t.Run，名字是「输入 → 期望」的中文短语。
t.Run("超长 query 按 rune 拒绝", func(t *testing.T) { ... })
```

| 项 | 规定 |
|---|---|
| 表驱动优先 | ≥3 个用例 MUST 用表驱动 |
| `t.Run` 名字 | 小写开头短句，不加空格编号（`"case1"` ❌） |
| 断言库 | **只用标准库** + `github.com/google/go-cmp/cmp`。MUST NOT 引入 testify。🔴 go-cmp 是**仅测试**依赖，只能出现在 `_test.go` 里 —— 「全项目 4 个第三方」说的是**运行时**口径，两者不矛盾（完整裁决见 `Contract/10-包依赖矩阵.md` §2.10.1）。业务代码引入 go-cmp 会让 `arch_test.go` 的 AR-1 当场红 |
| 并行 | 无共享状态的 L1 MUST 加 `t.Parallel()` |

### 2.1 标准表驱动模板（MUST 逐字使用骨架）

```go
func TestBuildQuery(t *testing.T) {
    t.Parallel()

    tests := []struct {
        name    string
        in      domain.SearchRequest
        want    string
        wantWarn []string
    }{
        {
            name: "只传 query 时原样透传",
            in:   domain.SearchRequest{Query: "生酮饮食"},
            want: "生酮饮食",
        },
        {
            name: "site 多个用 OR 连接",
            in:   domain.SearchRequest{Query: "go", Site: []string{"a.com", "b.com"}},
            want: "go site:a.com OR site:b.com",
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            t.Parallel()
            got, warns := domain.BuildQuery(tt.in)
            if got != tt.want {
                t.Fatalf("BuildQuery() = %q, want %q", got, tt.want)
            }
            if diff := cmp.Diff(tt.wantWarn, warns); diff != "" {
                t.Errorf("warnings 不符 (-want +got):\n%s", diff)
            }
        })
    }
}
```

| `internal/deepseek` | ≥ 70% | 有 HTTP 客户端胶水代码，部分难测 |
| `internal/tools` | ≥ 70% | handler 胶水较多 |

```bash
make cover        # 生成 coverage.out + 打印总覆盖率一行（快速反馈用）
make cover-check  # 逐包门槛判定，任一不达标退出非 0（规格见 §3.2，CI/发版 MUST 用这个）
make cover-html   # 生成 HTML 报告
```

🔴 **`make cover` 不能作为门槛判据**：它只 `go tool cover -func | tail -1` 打印一行总覆盖率，§三 的**逐包**门槛根本无法据此判定。发版闸门（`17-版本与发布契约` §七 第 10 项）与 CI cover job（`18-仓库文件契约`）MUST 一律引用 §3.2 的 `cover-check` 规格，MUST NOT 三处各写各的文字判据。

| `*_test.go` | 本身 |

### 3.2 `make cover-check` 完整规格（唯一真源；Makefile 本体归 Task-01 落地）

| 项 | 规格 |
|---|---|
| 输入 | `coverage.out`（由 `go test -count=1 -covermode=atomic -coverprofile=coverage.out ./...` 生成；`cover-check` MUST 依赖 `cover` 目标先跑） |
| 排除 | 判定前 MUST 从 profile 剔除 §3.1 三项（`cmd/deepseeksearch/main.go`、`internal/domain/codes.go`、`*_test.go`） |
| 逐包阈值 | `internal/domain` ≥ 80%、`internal/config` ≥ 80%、`internal/resilience` 根与 `ratelimit`/`retry`/`budget`/`circuit`/`cache` 五个子包各 ≥ 80%、`internal/deepseek` ≥ 70%、`internal/tools` ≥ 70%、`internal/transport` ≥ 60%（与 §三 表逐项相同） |
| 总阈值 | 排除后项目整体 ≥ 65% |
| 输出格式 | 每包一行：`cover-check: <包路径> <实际>% >= <阈值>% PASS/FAIL`；最后一行 `cover-check: TOTAL <实际>% >= 65% PASS/FAIL`；全过时追加 `cover-check: 全部包达标` |
| 非 0 退出条件 | 任一包低于其阈值，或 TOTAL < 65%，或 `coverage.out` 不存在/生成失败 ⇒ `exit 1` 并打印 FAIL 行。**MUST NOT 在任何门槛不达标时退出 0** |
| 实现方式 | 归 Task-01（Makefile 内联 awk 或独立脚本均可）；若新增脚本文件，MUST 同步登记进 `18-仓库文件契约` 的脚本清单，否则 `CheckRepoFiles.sh` 会拦 |

### 4.1 本轮审计新增的必测用例（MUST，缺一条对应 Task 的 DoD 不算完成）

**(a) 网络层错误 → 2998 的重试判定**（`14-错误契约` §1.2、ADR-016）

五种 `cause` 各一条用例，每条 MUST 断言：`code == 2998`、`IsRetryable == true`、`details.cause` 与 `details.attempt` 正确。

| # | 场景 | L1 构造方式 | `details.cause` |
|:-:|---|---|---|
| 1 | DNS 解析失败 | 注入返回 `no such host` 的假 resolver/dialer | `dns` |
| 2 | TCP 连接被拒 | dialer 指向无监听端口，或注入 `connection refused` | `tcp_connect` |
| 3 | TLS 握手失败 | `httptest.NewTLSServer` + 不信任其证书的 client | `tls_handshake` |
| 4 | 单次尝试超时 | server 睡过 `per_attempt_ms` 后 client ctx 到期 | `attempt_timeout` |
| 5 | 读体中断 | server 写完响应头后中途关闭连接 | `response_reset` |

理由：`14-错误契约` §六 承诺「网络层错误可重试」。没有这五条用例，2998 分支就没有任何测试证据，「可重试」仍是 ADR-016 修复前的那句空话。

**(b) `ToPayload` 的四步判定顺序**（`14-错误契约` §1.3）

四个分支各至少一条用例，MUST 按「先命中先返回」验证：

| 步 | 输入 | 期望码 |
|:-:|---|---|
| 1 | 实现 `domain.Coded` 的错误（如 `LocalError` 3000） | 用该码（3000） |
| 2 | `*UpstreamError`，`status=404` / `status=0` | 2404 / **2998** |
| 3 | 裸 `net.Error`、`context.DeadlineExceeded`、`io.ErrUnexpectedEOF`、`io.EOF` | **2998** |
| 4 | 其余一切（普通 `errors.New`、nil 被误传、panic 恢复后的 err） | **3099** |

MUST 含两条反例断言：**网络错误 MUST NOT 落进 3099**（外部问题被误报成我方 bug）、**我方 bug MUST NOT 落进 2999**（运维会被引去查上游）。2999 只允许由「HTTP 200 且解析/字段校验失败」产生。

**(c) 熔断只计 2xxx 可重试类失败**（`14-错误契约` §6.1）

- 正向：`2408` `2429` `2500` `2503` `2504` `2998` `2999` 七码各自连续 5 次 → 熔断 Open（表驱动，7 行）。
- 🔴 反例：**连续 5 次 3000（本地排队超时）MUST NOT 打开熔断**；1xxx（如 1070）同样不计入。
- 理由：若按「`err != nil` 即记失败」，本地限流拥塞会伪装成上游故障 → 熔断 Open → 之后全部返回 3030 —— 上游明明健康却拒绝服务，是**自我实现的故障放大**。

**(d) 重试预算冷启动**

- 冷启动用例：窗口（`retry.budget.window_s`=60s）内 `calls < 20` 时 MUST NOT 启用预算判定 —— `calls=1`、首次失败即 `retries/calls = 1/1 = 100% > ratio(0.10)`，重试仍 MUST 被放行。
- 满窗口用例：`calls ≥ 20` 且 ratio 超限 → 新重试被拒，返回 3010。
- 理由：无冷启动下限时，低 QPS 场景每次首败都触发 100% > 10%，`retry.enabled=true` **形同虚设**。
- ⚠️ 下限值 20 目前是测试规范定的固定值，`13-配置契约` §二 尚无对应键；是否升为配置键归 13 号/Task-06 裁决（已写入本轮报告）。

**(e) singleflight 的 Put/DELETE 时序与 owner panic**（Task-07 A-02）

- 时序用例：owner 删除 `inflight` 租约（DELETE）MUST 发生在缓存值写入（Put）**之后**。断言：owner + 等待者并发时，等待者拿到值且 `fetchCalls == 1`。反例后果：先 DELETE 后 Put 会让等待者看到「租约消失且缓存无值」⇒ 抢占租约**再打一次上游**（重复计费）或空等到 3075。
- panic 用例：owner 的 `fn` panic 时，MUST 经 `defer` 删除租约（MUST NOT 泄漏），等待者 MUST 在 `cache.wait_ms` 内拿到错误而非永久等待。断言：panic 恢复后 `inflight` 表为空。

**(f) SSRF：IPv4-mapped IPv6 与 IP 混淆**（Task-09 §3.2 第 4/4.1/5 条）

- 🔴 `http://[::ffff:127.0.0.1]/` 与 `http://[::ffff:7f00:1]/` MUST 拦（1070）：`netip` 对 IPv4-mapped 地址判 `127.0.0.0/8` 的 `Contains` 返回 **false**，不先 `Unmap()` 就等于给整张黑名单开后门。
- IP 混淆写法 MUST 覆盖 ≥6 种，全部拦（1070）：`2130706433`、`0x7f000001`、`017700000001`、`127.1`、`0x7f.0.0.01`、`0177.0.0.1`。
- 🔴 MUST 有一个**公网 IP 反例**（如 `8.8.8.8` 放行）—— 否则「全拦」的实现也能过测试。

**(g) `after:YYYY` 的展开**（23 号 §3.2.1 实测）

- 用例：`BuildQuery` 对 `after:"2026"` MUST 产出 `after:2026-01-01`；`after:"2026-10-01"` 原样保留；`before:"2026"` **不展开**（「早于该年」与直觉一致，23 号 §3.2.1）。
- 理由：实测 `after:2026` 对 2026-10 的内容返回 **0 条**（上游语义是「晚于该年」而非「该年起」），且上游对非法值静默忽略 —— LLM 几乎必然写裸年份，静默丢掉整年结果。

## 六、并发与竞态

| 规则 | 说明 |
|---|---|
| 🔴 **CI 与提交前 MUST 跑 `make test-race`；`make test` 仅用于本地快速反馈（不带 `-race`）** | 本项目大量并发（令牌桶、singleflight、缓存），不跑 race 等于没测。裁决理由：原「`make test` MUST 带 `-race`」与 §八 给出的 `test: go test -count=1 ./...`（不带）自相矛盾 —— 照前者要改 test 目标，照后者抄又违反前者。现统一为：门槛在 `test-race`，`test` 保持快 |
| 并发测试 MUST 用 `sync.WaitGroup` + `t.Parallel()`，MUST NOT `time.Sleep` 同步 | `Sleep` 会让测试在慢机器上随机失败 |
| `Singleflight` 测试 MUST 用 `atomic.Int64` 统计真实执行次数 | 断言 `execCount == 1`，不是「看起来没重复」 |
| `Limiter` 测试 MUST 用假 Clock 推进时间 | 否则测 60 rps 要真等 1 秒 |

## 八、Makefile 目标（Task-01 落地）

```makefile
.PHONY: test test-race test-integration cover cover-check cover-html lint

test:
	go test -count=1 ./...

test-race:
	go test -count=1 -race ./...

test-integration:
	go test -count=1 -tags integration -timeout 300s ./...

cover:
	go test -count=1 -covermode=atomic -coverprofile=coverage.out ./...
	go tool cover -func=coverage.out | tail -1

# cover-check：逐包门槛判定，规格见 §3.2（阈值/排除/输出/退出条件）。
# 实现体归 Task-01，MUST 依赖 cover 先产出 coverage.out。
cover-check: cover

cover-html: cover
	go tool cover -html=coverage.out -o coverage.html

lint:
	golangci-lint run ./...
```

| 规则 | 说明 |
|---|---|
| `-count=1` | 禁用测试缓存。缓存会让「改了代码测试还是绿的」 |
| 🔴 `test` 不带 `-race`、`test-race` 带 | CI 与提交前的门槛是 `make test-race`（§六）；`make test` 仅快速反馈。二者 MUST NOT 合并成一个口径含糊的目标 |
| `test` / `test-race` MUST 覆盖 L3a | L3a 协议测试不打 tag（T7），随这两个目标每次都跑；`test-integration`（L3b）只在人工触发时跑 |
| `test-integration` 超时 300s | Fetch 慢站实测可达 30s（23 号 §4.6 的 30 秒硬超时），2 次重试 + 3 个用例要留足 |
| `cover-check` MUST 按 §3.2 判定逐包门槛 | `make cover` 只打印总行，**不能**当门槛判据；发版与 CI 一律用 `cover-check` |
| 覆盖率文件 MUST 在 `.gitignore` 里 | 构建产物不提交 |

## 九、「测过了」的定义（DoD 测试部分）

一个原子任务声称「测试通过」MUST 同时满足：

| # | 条件 | 证据形式 |
|:-:|---|---|
| 1 | `make test-race` 全绿 | 粘贴实际输出（含 `ok` 行与总耗时） |
| 2 | `make lint` 零问题 | 粘贴实际输出（`0 issues`） |
| 3 | 本任务涉及的包覆盖率达标 | 粘贴 `go tool cover -func` 对应行 |
| 4 | 新增 `exported` 符号都有 `Test<Name>` | `grep -c '^func Test' ` 对照 |
| 5 | 规模红线自查通过 | 粘贴 `Scripts/CheckSize.sh` 输出 ¹ |

> ¹ **`CheckSize.sh` 由 Task-11 交付**。Task-01~10 的执行窗口里该脚本尚不存在，此时 MUST 以 `20-编码规范` §3.1 的自查命令替代并粘贴其输出，MUST NOT 因「文件不存在」而省略本条、也 MUST NOT 临时现写一个口径不同的脚本 —— 两者都破坏「DoD 全勾」的严肃性。

🔴 **没有新鲜命令输出的「测试通过」等于没测。** 不接受「应该没问题」「逻辑上是通的」。

## 十、反模式（code review 抓到即打回）

| # | 反模式 | 为什么 |
|:-:|---|---|
| A1 | 只 `if err != nil { t.Fatal(err) }` 不断言返回值 | 等于没测 |
| A2 | 断言 `err == nil` 却不检查内容 | 空实现的函数也能过 |
| A3 | 用 `time.Sleep` 等待并发完成 | 慢机器随机红 |
| A4 | 测试之间共享可变全局状态 | 单独跑绿、一起跑红 |
| A5 | `t.Skip` 无原因 | 静默漏测 |
| A6 | 编造黄金文件（手写假 JSON） | 契约是猜的，实现必然偏离真实上游 |
| A7 | 为通过覆盖率写「只调用不断言」的测试 | 覆盖率数字骗人 |
| A8 | 在 L1 里 import `net/http` 起真实服务 | L1 必须零 IO |
| A9 | 断言错误字符串原文（如 `err.Error() == "...(request_id: xxx)"`） | `request_id` 每次都变，测试必然红。MUST 断言 `errors.Is` 或提取后的字段 |
| A10 | 修改被测代码去迁就测试 | 测试是需求的表达，不是代码的影子 |
