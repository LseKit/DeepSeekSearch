## 一、豁免规则

| # | 规则 |
|:-:|---|
| E1 | 豁免 MUST 写明**实测值**，不能写「大约」 |
| E2 | 豁免 MUST 写明**不拆的具体理由**。「拆起来麻烦」不是理由 |
| E3 | 豁免 MUST 有**复核日期**（默认 3 个月后）。到期未复核视为失效 |
| E4 | 同一文件 MUST NOT 因同一个红线被豁免两次（说明上次没解决） |
| E5 | **每个窗口**新增豁免 MUST ≤3 条；规模基线的冻结项不占豁免额度。到第 4 条说明架构设计有问题，该改架构而不是加豁免 |

## 四、申请新豁免的流程

| 步 | 动作 |
|:-:|---|
| 1 | 先实测：`bash Scripts/CheckSize.sh . ../Doc`（在 `GitHubSrc/` 下）拿到确切数字。🔴 MUST 两个参数 —— 只传一个时 `DOC_ROOT` 退化为默认的 `Doc`（不存在）⇒ **本台账加载不到**，已登记的豁免全部失效、直接判 FAIL，你看到的数字就不是真实数字 |
| 2 | 自查：能不能通过**合并文件**（优先）或**提取子函数**解决 |
| 3 | 若确实不能：在 §二 的 `exempt` 块加一行 + 在 §2.1 表加一行说明 |
| 4 | 提交信息 MUST 写 `chore(exempt): 登记 <文件> 的 <红线> 豁免` |
| 5 | 复核日期到点前 MUST 重新评估一次 |

🔴 **MUST NOT** 用「把文件加进豁免」的方式通过 CI。豁免是**技术债**，不是通行证。
