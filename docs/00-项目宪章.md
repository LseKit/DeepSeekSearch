## 一、项目定位

DeepSeekSearch 是一个 **MCP 服务端**，把 DeepSeek 的 `POST /v1/tools/search` 与 `POST /v1/tools/fetch` 两个原始 JSON API 封装成 MCP Tool，供 LLM Agent 调用。

**它不做什么**（非目标，任何 PR 越界即驳回）：

| 非目标 | 理由 |
|---|---|
| 不做检索增强的二次加工（不调用任何 LLM 做摘要/重写） | 一次工具调用 = 一次 HTTP 请求，延迟与费用可预测 |
| 不实现爬虫 | 抓取完全委托 DeepSeek Fetch API |
| 不实现 SSE 传输（阶段一） | 2026-07-28 规范只定义 stdio 与 Streamable HTTP 两种 binding；HTTP+SSE 属 2024-11-05 且已 Deprecated |
| 不实现多租户 | 单用户自用工具；HTTP 传输提供可选 Bearer 鉴权（`auth_enabled`），也可交给前置网关 |
| 不做 Web UI | 纯 MCP Server |

## 二、三种传输协议（阶段一交付范围）

| # | 传输 | 状态 | 依据 |
|---|---|---|---|
| 1 | **stdio** | 必须实现 | 覆盖 Claude Desktop / Cursor / Codex / Hermes 等本地客户端 |
| 2 | **Streamable HTTP（无状态，严格 2026-07-28）** | 必须实现 | `StreamableHTTPOptions.Stateless = true`，单端点 `/mcp` |
| 3 | **HTTP+SSE** | **不实现**，但保留扩展点 | 见 ADR-002 |

**扩展点要求（硬性）**：`Transport` 包 MUST 定义 `Handler` 接口，新增传输方式 = 新增 1 个实现文件 + `config.toml` 加 1 行，`Tools` / `DeepSeek` / `Domain` 三个包 **零改动**。

## 三、规模红线（可判定，不可换算）

来源：Go 官方标准库实测锚定 + 本项目自订纪律。

| 判据 | 阈值 | 载体 | 计数口径 | 违反后果 |
|:-:|-|-|-|-|
| **F-S1** 单文件行数 | **≤ 600** | `revive/file-length-limit` | **含空行、含注释** | `make lint` 失败 |
| **F-S2** 单函数行数 | **≤ 50** | `funlen/lines` | **不含注释** | 同上 |
| **F-S3** 圈复杂度 | **≤ 10** | `cyclop` | 1 + 分支/循环/case | 同上 |
| **F-S4** 嵌套深度 | **≤ 3** | `nestif` | 累加复杂度 | 同上 |
| **F-S5** 每包生产行数 | **≤ 3000** | 架构适应度测试 | 非 `_test.go` 的 LF 总数 | `make test` 失败 |
| **F-S5** 每包生产文件数 | **≤ 10** | 同上 | 同上 | 同上 |
| **F-S5** 每包导出符号数 | **≤ 20** | 同上 | `go/doc` 语义 | 同上 |
| **F-S6** 豁免台账 | 四要素齐全 + 未过期 | 同上 | — | 同上 |

### 3.1 为什么是这三个数字

| 数字 | 来源 | 不是拍的 |
|---|---|---|
| 600 行/文件 | Go 标准库 4,331 个非生成文件实测：中位 111、P75 316、**P90 689**。600 ≈ P87 | Google / Uber Style Guide **都不给**行数上限，所以这是本项目自订纪律 |
| 50 行/函数 | 比工具默认 60 更严；一个函数要能被一眼看完 | 超过 50 行的函数，控制流无法在短时记忆内穷举 |
| 3000 行/包 | 标准库包规模 **P90 ≈ 3100** | 包是 Go 的编译与封装单元，包太大等于没有封装 |

**核心纪律（必须记住的理由）**：上限写到哪，文件就长到哪。曾有项目把上限设 1000，实际最大单文件 976 行（97.6% 贴线）。**所以上限必须比"能接受"更严一档。**

### 3.2 三个维度独立取严，MUST NOT 相互换算

包内 12 个文件但总行数 800 行 —— **仍然超限**（文件数维度独立触发）。
反之 3 个文件 3500 行 —— **也超限**（行数维度独立触发）。

### 3.3 豁免机制（不是"不许豁免"，是"必须留痕"）

豁免 MUST 在 `docs/Engineering/豁免台账.md` 登记四要素：路径 / 实际数值 / 理由 / 到期日。`CheckSize.sh` 读取该台账；到期复核目前由人工执行，没有自动过期测试。

**MUST NOT 使用 `//nolint` 注释豁免** —— 它绕过台账，等于不留痕。

## 四、代码切分规则

### 4.1 单文件超限时怎么切

| 规则 | 内容 |
|---|---|
| 最小搬移单位 | **完整的顶层声明**（`var` / `const` / `type` / `func` 整块）。Go 编译单元是包不是文件，同包拆文件零引用改动 |
| 命名 | 新文件名 MUST 反映内容职责（`SearchRequest.go` / `SearchResponse.go`），MUST NOT 用 `part2` / `util` / `common` / `helpers` |
| 禁止 | 切开函数体；为压行数新建子包；用切文件代替重构；通配符豁免；`//nolint` |

### 4.2 单函数超限时怎么切

只允许 Extract Method，且必须满足下列之一：

| 提取目标 | 判据 |
|---|---|
| 纯计算 | 提取段不读写外部状态，输入输出全是参数/返回值 |
| 卫语句 | 提前返回的分支，提取后主流程线性可读 |
| 准备与收尾阶段 | 入参校验 / 结果组装，与核心算法解耦 |
| 循环体 | 单次迭代的语义能被一个动词命名 |
| 错误处理 | 错误分类与转换独立成函数 |

**禁止**：为做短而抽只被调用一次、无独立语义的函数。这种"函数碎片化"比长函数更难读。

### 4.3 包级 `var` / `init()` 搬移禁令

Go 规范里跨文件的初始化顺序**只是 encouraged，不是 guaranteed**。涉及包级 `var` 或 `init()` 的搬移 MUST 补一条初始化顺序测试。

## 五、依赖方向（单向，无环）

```
cmd/deepseeksearch  →  transport, tools, config, deepseek, resilience, logging, domain
Transport          →  Config, Domain
Tools              →  DeepSeek, Resilience, Config, Domain
Resilience         →  Domain
DeepSeek           →  Domain
Config             →  Domain
Domain             →  (仅标准库)
```

**MUST NOT 出现反向 import。** 由 `docs/Contract/10-包依赖矩阵.md` 逐包白名单写死，脚本比对，白名单外 import 直接失败。

## 六、配置分层（硬性）

| 文件 | 内容 | 权限 | 规则 |
|---|---|---|---|
| `Config/config.toml` | 全部非敏感配置 | 644 | MUST NOT 出现任何密钥值 |
| `Config/.env` | `DEEPSEEK_API_KEY` + 可选 `DEEPSEEKSEARCH_HTTP_TOKEN` | **600** | 仅这两个变量 |
| 环境变量 | 同 `.env` | — | 优先级高于 `.env` |

**启动时强制校验**：`config.toml` 内出现键名匹配 `(?i)(key\|token\|secret\|password\|credential)` 的字段 → **拒绝启动**并打印违规行号。用代码强制，不靠自觉。

**为什么 TOML 不用 YAML**：
1. YAML 1.1 的 `no` / `on` / `yes` / `off` 会被隐式解析为布尔（挪威问题），PyYAML 至今默认 1.1；
2. 缩进敏感 + 禁用 tab，缩进地狱；
3. 锚点/别名/多文档让配置无法静态分析；
4. TOML 类型严格，解析失败即报错，不静默错值。

## 七、错误与日志（硬性）

### 7.1 错误码

**每个错误码独立返回，MUST NOT 混用。**

- 我方错误码格式：`DS_E_<域><4位数字>`，域分 `VAL`（入参）/ `UP`（上游）/ `LOC`（本地资源）。完整表见 `docs/Contract/14-错误契约.md`。
- 上游 HTTP 状态码 MUST 原样保留在返回结构中（`upstream_http`）。
- 上游 `request_id` MUST 从错误消息中提取并单独返回，供排查与工单。
- MCP 层 MUST 返回 `isError: true`，MUST NOT 用"正常返回 + 错误文案"的方式伪装成功。

### 7.2 日志

| 项 | 规定 |
|---|---|
| 格式 | JSON（`log/slog`），一行一条 |
| 输出 | 同时写 stderr 与文件 `Logs/DeepSeekSearch.log` |
| 轮转 | 按自然日与单文件大小双上限轮转，参数全部可配：`max_size_mb` / `daily_max_mb` / `max_backups` / `max_age_days` / `compress` |
| 脱敏 | API Key MUST NOT 落盘（一个字符都不记）；URL 的 query 中追踪参数不记 |
| 级别 | `debug` / `info` / `warn` / `error`，可配 |
| 必须记录 | 每次上游调用记：工具名 / 上游 HTTP / 上游 request_id / 耗时 / 是否命中缓存 / 我方错误码 |

## 八、安全底线

| 项 | 规定 |
|---|---|
| SSRF | 我方 MUST 实现独立 host 黑名单（私网段 / loopback / 链路本地 / 云元数据 IP），**不依赖上游拦截**。只判字面量 host，**不做 DNS 解析**（DNS 重绑定不在受理范围，理由见 `SECURITY.md`）。实测上游对这些全部返回 404，与真实 404 无法区分；且 `base_url` 一旦被改指向自建代理，上游保护即消失 |
| API Key | 只从 env / `.env` 读，MUST NOT 出现在 config.toml、日志、错误消息、MCP 返回值中 |
| 抓取内容 | Fetch 返回的正文 MUST 被包裹在显式分隔符内，并标注 `untrusted: true`。理由：正文无任何清洗直接进 LLM 上下文，存在 prompt injection 面 |
| 反向代理 | 部署文档 MUST 说明：反代 MUST 透传 `Mcp-Method` / `Mcp-Name` / `MCP-Protocol-Version` 三个头，改写或丢弃会导致合规请求被判 400 |

## 十、术语表

| 术语 | 定义 | 禁用同义词 |
|---|---|---|
| **上游** | `api.deepseek.com` 的 Search / Fetch API | 服务端、远端 |
| **工具（Tool）** | 我方注册给 MCP 客户端的 `ds_search` / `ds_fetch` / `ds_health` / `ds_research` / `ds_extract` | 接口、方法 |
| **协议** | MCP 规范版本，当前 `2026-07-28` | 标准、版本号 |
| **传输** | 承载 MCP 消息的通道：`stdio` / `streamable-http` | 通道、连接方式 |
| **无状态** | 请求不带 session、每次自描述、可落任意实例 | 会话无关 |
| **规范化 URL** | 剥追踪参数后的 URL，见 `docs/Contract/12-数据契约.md` §URL 规范化 | 清洗 URL |
| **预算** | 单次工具调用允许返回的最大字符数 | 限额、配额 |
| **硬顶** | 达到即拒绝执行、不向上游发起请求的本地阈值 | 熔断、上限 |
