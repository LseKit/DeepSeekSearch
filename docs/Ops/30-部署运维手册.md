## 一、部署目录（PascalCase，与 `GitHubSrc/` 分离）

```
/mcp/DeepSeekSearch/
├── GitHubSrc/          ← git 仓库，只放源码
├── Bin/
│   └── DeepSeekSearch  ← 唯一可执行文件
├── Config/
│   ├── config.toml     ← 644，非敏感配置
│   └── .env            ← 600，只有 DEEPSEEK_API_KEY（+ 可选 token）
├── Data/
│   └── Cache.db        ← SQLite（自动创建）
├── Logs/               ← 按日期命名的日志（自动创建，自动清理 7 天）
├── Scripts/            ← 运维脚本
└── Ecosystem/          ← PM2 / systemd / nginx 片段
```

🔴 **铁律**：程序 MUST NOT 在项目目录外写任何文件。所有运行时数据都在 `Data/` 与 `Logs/`。

## 二、首次部署（5 步）

```bash
# 1. 放二进制
install -m 0755 Bin/DeepSeekSearch_v0.1.0_linux_amd64 Bin/DeepSeekSearch

# 2. 配置
cp GitHubSrc/config.example.toml Config/config.toml

# 3. 密钥（权限必须 600，否则拒绝启动）
printf 'DEEPSEEK_API_KEY=%s\n' 'sk-你的真实key' > Config/.env
chmod 600 Config/.env

# 4. 校验（不建目录、不起服务）
./Bin/DeepSeekSearch -check -config Config/config.toml

# 5. 起服务
./Bin/DeepSeekSearch -transport streamable-http -config Config/config.toml
```

> **`-env` 口径（全手册统一）**：上面两步都**不带** `-env` —— `-env` 的默认值就是 `Config/.env`（相对运行目录解析，见 Task-12 的 flag 定义），`Config/.env` 会被自动发现，§四 systemd 的 `ExecStart` 同理不带。只有当 `.env` 放在非默认路径时才显式传 `-env <路径>`。

> **端口口径**：下文示例沿用默认端口 `8765`；本机现行部署为形态 D 的 `0.0.0.0:20010`（§3.2 / §4.1），把示例里的 `8765` 换成 `20010` 即可。

### 2.1 首次部署的 4 项必查

| # | 检查 | 命令 |
|:-:|---|---|
| 1 | tzdata 存在 | `./Bin/DeepSeekSearch -check` 不报时区错误 |
| 2 | `.env` 权限 | `stat -c '%a' Config/.env` = `600` |
| 3 | 端口可用 | `ss -lntp \| grep 8765` 为空 |
| 4 | 健康检查 | `curl -s localhost:8765/healthz \| jq .version` 输出 `"v0.1.0"` |

## 三、四种典型部署形态

| 形态 | 适用 | 配置要点 |
|---|---|---|
| **A. stdio 本地** | Hermes / Qoder / Claude Desktop / Cursor 在本机 | `transport="stdio"`，不需要 `[server.http]`。**每个客户端一个进程**（缓存靠 SQLite 共享） |
| **B. Streamable HTTP 本机** | 多个本机客户端共享一个进程 | `host="127.0.0.1"`，`auth_enabled=false`（合法） |
| **C. 反代 + 鉴权** | 局域网 / 网关 / MCPMesh | `host="127.0.0.1"` + `allow_non_local_host=true` + `auth_enabled=true` + token 在 `.env` |
| **D. 直连局域网** | 内网自用、不挂反代（本机现行） | `host="0.0.0.0"` + `allow_non_local_host=true`；`auth_enabled` 可选（false 会打 3092 警告，true 时 token 放 `.env`） |

### 3.1 形态 C 的完整要求（少一项就 403 或裸奔）

```toml
[server]
transport = "streamable-http"

[server.http]
host = "127.0.0.1"              # 反代在本机，所以只听回环
allow_non_local_host = true     # 🔴 反代会转发原始 Host，不开这个全 403
auth_enabled = true             # 形态 C 要求鉴权；不鉴权也能启动，但会打 3092 警告（ADR-018）
```

```bash
echo 'DEEPSEEKSEARCH_HTTP_TOKEN=<32字节随机串>' >> Config/.env
chmod 600 Config/.env
```

```nginx
location /mcp {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Authorization $http_authorization;  # 🔴 必须显式透传
    proxy_buffering off;
    proxy_read_timeout 180s;                              # 必须 > fetch total_timeout_ms
    proxy_pass_request_headers on;
}
location /healthz {
    proxy_pass http://127.0.0.1:8765;                     # 探活不鉴权，可不带 token
}
```

🔴 反代 MUST 透传的头：`Mcp-Method`、`Mcp-Name`、`MCP-Protocol-Version`。部分反代默认丢弃未知头，`Mcp-*` 就是未知头。

### 3.2 形态 D 的完整要求（直连局域网，本机现行）

不走反代，客户端直接连端口。`host` 写 `"0.0.0.0"` 或本机网卡 IP 要求相同：

```toml
[server]
transport = "streamable-http"

[server.http]
host = "0.0.0.0"                # 也可写本机网卡 IP，如 "10.10.10.245"
port = 20010
allow_non_local_host = true     # 🔴 局域网的 Host 头是 IP，不开这个全 403（3093）
auth_enabled = false            # 可选开关（ADR-018）：false = 不鉴权（启动打 3092 警告）；true = 要求 Bearer
```

```bash
# 仅当 auth_enabled = true 时需要：
echo 'DEEPSEEKSEARCH_HTTP_TOKEN=<≥16字节随机串>' >> Config/.env
chmod 600 Config/.env
```

客户端 URL：`http://10.10.10.245:20010/mcp`；`auth_enabled = true` 时请求头带 `Authorization: Bearer <token>`，为 `false` 时免凭据。

🔴 直连没有任何来源限制：不鉴权时任何能连上该端口的人都能调用并按次计费（¥0.005/次成功调用），启动日志会打印 3092 警告。`/healthz` 在鉴权与 Host 校验之前，可匿名探活。

## 四、进程守护（PM2 现行 / systemd 备选）

🔴 两者**只能启用其一** —— 争用同一个监听端口。本机现行用 PM2；systemd 单元保留为备选，切换前先停另一个。

### 4.1 PM2（本机现行）

守护配置是仓库外的 `Ecosystem/ecosystem.config.js`（Go 静态二进制，`interpreter: 'none'` 直跑，不经 shell 包装）。关键约束：

| 参数 | 值 | 为什么 |
|---|---|---|
| `cwd` | 部署根 | `-config Config/config.toml` 相对 cwd 解析，cwd 错会报 3040 |
| `instances` | `1` | SQLite 单写者；限流/熔断/singleflight/预算都是**进程内**状态，多实例 = N 倍账号级 QPS |
| `kill_timeout` | `30000` | 优雅关闭最坏链 = HTTP `Shutdown` 15s + 租约释放 5s + 缓存关闭（含 hits 落盘）5s ≈ **25s**；PM2 默认 1600ms 会在排空中途 SIGKILL，丢在途计费调用。🔴 20000 也不够：SIGKILL 会落在租约释放**之前**，留下要等 TTL 才消失的租约行（2026-10-25 审计） |
| `restart_delay` | `5000` | 留出监听端口 TIME_WAIT 释放时间 |
| `max_memory_restart` | `512M` | 常驻约 15M，留足 fetch 大响应缓冲 |
| `wait_ready` | **不设** | Go 进程没有 PM2 IPC，设了会永远 pending；就绪判定用 `/healthz` |
| `env` | 不注入密钥 | `pm2 save` 把 env 明文写进 `dump.pm2`；API Key / token 只放 `Config/.env` |

```bash
export PM2_HOME=/agent/Tools/PM2/Data    # 🔴 不设会另起 daemon 到 ~/.pm2，开机 resurrect 找不到本进程
pm2 start Ecosystem/ecosystem.config.js
pm2 save                                  # 🔴 开机由 pm2-ada.service 执行 pm2 resurrect

pm2 status
curl -s localhost:20010/healthz | jq '{status,version}'   # 就绪判据
```

- 改 `Config/config.toml` / `.env` 后：`pm2 restart DeepSeekSearch`
- 改 `Ecosystem/ecosystem.config.js` 后：`pm2 restart Ecosystem/ecosystem.config.js`
- PM2 日志：`Logs/PM2Out.log`、`Logs/PM2Err.log`，由已安装的 `pm2-logrotate` 轮转；程序自身日志在 `Logs/DeepSeekSearch_YYYYMMDD_HHMMSS_PID.log`
- 🔴 PM2 只看进程存活，不做应用层健康判定：探活靠 cron 打 `/healthz`（§5.2）

### 4.2 systemd 单元（备选）

如需改用 systemd，创建 `Ecosystem/deepseeksearch.service`（内容如下；本机当前未安装、未启用）：

```ini
[Unit]
Description=DeepSeekSearch MCP server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=agent
WorkingDirectory=/mcp/DeepSeekSearch
# 🔴 -env 已统一移除：`-env` 的默认值就是 Config/.env（见 Task-12 的 flag 定义），
#    相对 WorkingDirectory 解析 —— 自动发现成立，显式传参是冗余的。
#    本手册所有启动/校验命令（§二、§7.1~§7.3）一律不带 -env，两处口径统一。
ExecStart=/mcp/DeepSeekSearch/Bin/DeepSeekSearch -transport streamable-http -config Config/config.toml
Restart=on-failure
RestartSec=3s
# 🔴 只让 /mcp/DeepSeekSearch 可写
ProtectSystem=strict
ReadWritePaths=/mcp/DeepSeekSearch/Data /mcp/DeepSeekSearch/Logs
NoNewPrivileges=true
PrivateTmp=true
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

**为什么 `LimitNOFILE=65536`**：默认 1024 时，`max_inflight=8` 加上客户端连接、SQLite 连接、上游连接，在并发爬升时会 `EMFILE`。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now deepseeksearch
systemctl status deepseeksearch
journalctl -u deepseeksearch -n 50 --no-pager
```

## 五、SLO 与容量

| 指标 | 目标 | 观测点 |
|---|:-:|---|
| 可用性 | 99.5%（自用工具，不承诺 99.9） | `/healthz` 200（§5.2 外部探针，**日志无法自证可用性**） |
| `ds_search` P95 | < 5s | 日志 `call.end` 的 `ms`（§5.2 周报脚本） |
| `ds_fetch` P95 | < 15s | 同上 |
| 错误率 | < 2% | `err` 事件数 / `call.end` 数（§5.2 周报脚本） |
| 缓存命中率（fetch） | > 40%（同一批搜索结果二次抓取场景） | `call.cache` 的 `hit`（§5.2 周报脚本） |
| 磁盘（`Data/`） | < 300MB | 配置 `cache.max_bytes_mb=256` 自动 LRU |
| 磁盘（`Logs/`） | < 3.5GB（7 天 × 500MB 上限） | 自动清理 |

🔴 上表此前只有「观测点」字段名而**没有任何采集管道** ⇒ 99.5% 根本不可度量。度量管道 = §5.2 的探针（可用性）+ 周报脚本（其余指标），两者都挂 cron。

### 5.2 SLO 度量管道（探针 + jq 周报脚本）

**可用性 MUST 用外部探针**：进程挂掉时不会写日志，「可用性」不可能从 `Logs/` 自证。探针把每次 `/healthz` 的结果追加到 `Data/probe.log`（在项目目录内，不违反「不外写」铁律）：

```bash
# /healthz 探针（每 5 分钟一次，挂 cron，见下）。200 = UP，其它/超时 = DOWN。
printf '%s %s\n' "$(date +%F_%T)" \
  "$(curl -s -o /dev/null -m 5 -w '%{http_code}' localhost:8765/healthz)" \
  >> /mcp/DeepSeekSearch/Data/probe.log
```

**其余四项指标从 `Logs/` 的 JSONL 算**（事件与字段名见 Task-04 A-02 事件表：call.end 带 `tool`/`ms`/`billed`，err 带 `code_name`，call.cache 带 `hit`）。部署时把下面全文保存为 `Scripts/slo_weekly.sh`（仓库不预置该脚本）：

```bash
#!/usr/bin/env bash
# 文件名: slo_weekly.sh
# 用途: 从 Logs/ 的 JSONL 与 Data/probe.log 计算 SLO 周报（§五 表的全部指标）。
# 创建日期: 2026-10-20
# 作者: 小逸
# 项目: DeepSeekSearch <https://github.com/LseKit/DeepSeekSearch>
set -uo pipefail
cd /mcp/DeepSeekSearch

# 1) 可用性：探针成功率（目标 ≥ 99.5%）
if [ -f Data/probe.log ]; then
  awk '{n++; if ($2=="200") up++} END {printf "availability=%.4f (%d/%d)\n", up/n, up, n}' Data/probe.log
fi

# 2) P95 / 错误率 / fetch 缓存命中率：jq 一次算完（对最近 7 天的日志）
jq -rs '
  (map(select(.msg=="call.end"))) as $ends
  | ([$ends[] | select(.tool=="ds_search") | .ms] | sort) as $s
  | ([$ends[] | select(.tool=="ds_fetch")  | .ms] | sort) as $f
  | {
      calls:          ($ends | length),
      search_p95_ms:  (if ($s|length)>0 then $s[(($s|length)-1)*0.95|floor] else null end),
      fetch_p95_ms:   (if ($f|length)>0 then $f[(($f|length)-1)*0.95|floor] else null end),
      err_rate:       ((map(select(.msg=="err")) | length) / ([$ends|length, 1] | max)),
      fetch_cache_hit_rate:
        ( (map(select(.msg=="call.cache" and .tool=="ds_fetch"))) as $cc
          | if ($cc|length)>0 then ($cc | map(select(.hit==true)) | length) / ($cc|length) else null end )
    }' Logs/*.log 2>/dev/null

# 3) 计费口径交叉核对：billed=true 的 call.end 数 × ¥0.005 ≈ 本周成本
jq -s '[.[] | select(.msg=="call.end" and .billed==true)] | length' Logs/*.log 2>/dev/null
```

**挂 cron**（`crontab -e`；注意 crontab 里字面 `%` MUST 写成 `\%`）：

```
*/5 * * * * printf '%s %s\n' "$(date +\%F_\%T)" "$(curl -s -o /dev/null -m 5 -w '\%{http_code}' localhost:8765/healthz)" >> /mcp/DeepSeekSearch/Data/probe.log
0 9 * * 1 cd /mcp/DeepSeekSearch && bash Scripts/slo_weekly.sh > "Data/slo-$(date +\%F).json" 2>&1
```

| 注意点 | 说明 |
|---|---|
| 日志 7 天滚动清理 | 周报 MUST 在清理窗口内跑（每周一 09:00 算上周恰好覆盖）；跨更长时间的 SLO 趋势靠每周把 `Data/slo-*.json` 归档 |
| `Logs/` 里的 `.gz` | 脚本只算未压缩的 `.log`；被 gzip 的历史文件如需纳入，先 `zcat` 到临时 `.log` |
| 配额丢行 | 若日志触发 `warn.log_quota`（`log.daily_max_mb` 封顶），当周指标是**下限估计**；周报里应同时 grep 该事件出现次数 |
| stdio 形态（A） | 无 `/healthz` 可探 ⇒ 可用性指标只对形态 B/C 有意义；形态 A 用「客户端会话失败率」代替（暂不自动化，人工记） |

### 5.1 成本估算

| 项 | 值 |
|---|---|
| 单价 | ¥5 / 1000 次（Search 与 Fetch 各自计费） |
| 单次 `ds_search` | ¥0.005 |
| 单次 `ds_fetch` | ¥0.005 |
| 典型一轮「搜索 + 抓 3 页」 | ¥0.02 |
| 缓存命中 | ¥0 |

## 六、故障排查（症状 → grep → 结论）

### 6.1 日志字段速查

```bash
# 看最近一次调用链路
grep '"call_id":"<id>"' Logs/DeepSeekSearch_*.log | jq -c '{t:.time,ev:.msg,ms:.ms,billed:.billed}'

# 看错误分布
jq -r 'select(.msg=="err") | .code_name' Logs/*.log | sort | uniq -c | sort -rn

# 看慢调用
jq -r 'select(.msg=="warn.slow") | "\(.tool) \(.ms)ms"' Logs/*.log | sort -k2 -rn | head -20
```

### 6.2 症状表

| 症状 | 先 grep 什么 | 可能的结论 | 处理 |
|---|---|---|---|
| 客户端连不上 | `app.ready` 有没有 | 进程没起来 / 端口不通 | 看 `journalctl`，`ss -lntp` |
| 连上了但无响应 | `app.transport` | stdio 下 stdout 被污染 | 查是否有人 `fmt.Println` |
| 全部 403 | `3093` 或 `invalid Host header` | `3093` = 本项目 hostGuard（反代/直连没开 `allow_non_local_host`）；`invalid Host header` = SDK 的 DNS 重绑定防护（回环监听收到非回环 Host） | 前者开 `allow_non_local_host` + 鉴权；后者开 `disable_localhost_protection`（危险开关，见 13 号 §七） |
| 全部 401 | `3091` | token 未透传 | nginx 加 `proxy_set_header Authorization` |
| 全部 429 | `2429` | 客户端并发过高 | 降 `ratelimit.search.rps` |
| 全部 402 | `2402` | 余额不足 | 充值。**重试无用** |
| 全部 404（搜不到） | `2404` | 上游塌缩，见 7 种成因 | 换关键词 / 换站点 |
| 抓取很慢 | `call.upstream.done` 的 `ms` | 目标站慢 | 正常；已设 per_attempt 45s |
| 抓取 504 | `2504` | 目标站超 30s | 换源；或调大 `fetch.per_attempt_ms` |
| 缓存不命中 | `call.cache` 的 `hit=false` | search TTL 仅 180s（ADR-014），过期即新请求；或 fetch 超 `ttl_fetch_s` | 属正常；短窗口内同 query 才会命中 |
| 缓存总是 MISS | `warn.cache_degraded` | SQLite 打不开 | 查 `Data/` 权限 |
| 配置改了不生效 | `config_sha256` 有没有变 | 改了别的文件 / 未知键被拦 | `-check` 看实际值 |
| 磁盘一直在涨 | `warn.log_quota` | 日志超配额 | 降 `log.daily_max_mb` |
| 进程被 OOM kill | 抓取 `total_chars` | 超大页面 | 降 `upstream.max_response_bytes` |
| 版本显示 `v0.0.0-dev` | — | 直接 `go build` 没用 Makefile（**仅限开发机自测**） | 用 `make build` |

> 🔴 **NUC / HPE 上 MUST NOT 构建发布产物**：三机 Go 版本虽已于 2026-10-21 统一为 1.27.2，但各自构建仍会因**构建时间、commit、GOAMD64 等**产生不同二进制，`--version` 与 `SHA256SUMS` 都不一致。发布产物 MUST 在 CI 构建一次，部署机只**下载 + 校验 + install**（见 §7.1）。

### 6.3 五个高频误区

| 误区 | 事实 |
|---|---|
| 「403 是安全策略拒绝」 | 官方文档这么写，但**实测已塌缩成 404**。区分不了 |
| 「上游有 QPS 5 限制」 | 两端点分别限速（23 号 §6.1/§6.2）：fetch **25 QPS 硬上限**（60 并发实测 28 个 429），search 40 并发零 429。默认 `ratelimit` search rps=30 / fetch rps=20 |
| 「`ori_question` 能提升效果」 | 实测 4 组里 3 组字节级相同 |
| 「同一 URL 并发抓会返回不同长度」 | **已被推翻**（23 号 §4.6）：成功的并发响应 sha256 全等；真实的并发失败模式是部分请求 **504@30s**（上游网关硬超时）。旧记载「5 种长度」不再成立 |
| 「缓存能省 Search 的钱」 | **能，但窗口很短**：同 query 短窗口内字节级稳定（23 号 §3.4 连续 3 次 sha256 全等），故 `ttl_search_s = 180`（ADR-014 已把旧值 0 改掉；「4 次字节数不同」的旧立论出自跨小时/跨天的索引更新） |

## 七、日常运维任务

| 频率 | 任务 | 命令 |
|---|---|---|
| 每日 | 看错误率 | `jq -r 'select(.msg=="err")\|.code_name' Logs/*.log \| sort \| uniq -c` |
| 每周 | 看磁盘 | `du -sh Data/ Logs/` |
| 每周 | 看缓存效率 | `curl -s localhost:8765/healthz \| jq .cache` |
| 每月 | 清缓存（可选） | 停服 → `rm Data/Cache.db*` → 起服（会重建） |
| 按需 | 校验配置 | `./Bin/DeepSeekSearch -check` |

### 7.1 升级流程（秒级停机）

🔴 **标题裁决**：原标题「零停机可选」名不副实 —— 下方流程就是 stop → mv → install → start 的**停机升级**，手册也没有提供任何零停机手段，已改正。本项目**不做**零停机方案：自用工具、systemd `RestartSec=3s`、形态 A/B 的客户端对秒级中断无感；真零停机（双实例 + 反代切换，或 socket activation）的复杂度远超收益。形态 C 用户若确有需要，可在反代层先把实例 drain 掉再升级（nginx upstream 双实例配置超出本手册范围）。

```bash
# 1. 下载新版本 + 校验
sha256sum -c SHA256SUMS --ignore-missing

# 2. 先校验配置兼容性（新版本可能加/删配置项）
./Bin/DeepSeekSearch_v0.2.0_linux_amd64 -check -config Config/config.toml

# 3. 备份当前配置（🔴 必做：新版本若改了配置语义，只回滚二进制不回滚配置会起不来）
#    ${VERSION} = 升级前正在运行的旧版本号（如 v0.1.0）
cp Config/config.toml "Config/config.toml.bak.${VERSION}"

# 4. 换二进制（按现行守护方式二选一）
pm2 stop DeepSeekSearch            # PM2 形态（本机现行）
# systemctl stop deepseeksearch    # systemd 形态（备选）
mv Bin/DeepSeekSearch Bin/DeepSeekSearch.old
install -m 0755 Bin/DeepSeekSearch_v0.2.0_linux_amd64 Bin/DeepSeekSearch
pm2 start DeepSeekSearch
# systemctl start deepseeksearch

# 5. 验证（端口以实际配置为准，本机为 20010）
curl -s localhost:20010/healthz | jq '{version,commit,cache}'
```

🔴 **升级 MUST NOT 动 `Data/Cache.db`**。表结构变更需要 ADR + 迁移脚本，`v0.1.0` 的 schema 在后续版本中保持兼容。

### 7.2 回滚

回滚 = 二进制 + 配置 + 验证三件事，缺一即可能「回滚了但起不来 / 起来了但语义不对」：

```bash
pm2 stop DeepSeekSearch          # systemd 形态改用 systemctl stop deepseeksearch
mv Bin/DeepSeekSearch Bin/DeepSeekSearch.failed

# ① 二进制回滚，分两种情形：
if [ -f Bin/DeepSeekSearch.old ]; then
    # A. .old 存在（§7.1 第 4 步刚产生的）→ 直接换回
    mv Bin/DeepSeekSearch.old Bin/DeepSeekSearch
else
    # B. .old 不存在（全新安装后直接回滚、或 .old 已被上一轮回滚消耗）
    #    → 从发布产物重装目标旧版本（与正常下载同一渠道，先过 sha256）
    install -m 0755 Bin/DeepSeekSearch_v0.1.0_linux_amd64 Bin/DeepSeekSearch
fi

# ② 配置回滚：若升级时备份过配置（§7.1 第 3 步），恢复之；没有备份则先 -check 现配置
if [ -f "Config/config.toml.bak.${VERSION}" ]; then
    cp "Config/config.toml.bak.${VERSION}" Config/config.toml
fi
./Bin/DeepSeekSearch -check -config Config/config.toml   # MUST 通过才允许 start

# ③ 起服 + 验证（此前缺这一步：回滚后不验证 = 不知道回滚是否成功）
pm2 start DeepSeekSearch        # systemd 形态改用 systemctl start deepseeksearch
curl -s localhost:20010/healthz | jq '{version,commit,cache}'   # version MUST 显示旧版本号
pm2 status DeepSeekSearch                                        # 期望 online
```

### 7.3 形态 A（stdio）的升级 / 回滚

stdio 进程由客户端（Hermes / Qoder / Claude Desktop / Cursor）按需 spawn，客户端配置里登记的是二进制**路径**（`/mcp/DeepSeekSearch/Bin/DeepSeekSearch`），路径不变则客户端配置不用改：

```bash
# 原子替换：先落到同目录临时名再 mv（同一文件系统内 rename 是原子的）。
# 🔴 MUST NOT 直接 cp 覆盖正在运行的二进制 —— Linux 会 ETXTBSY，
#    某些平台上还会让已 mmap 旧文件的进程读到半新半旧的字节。
install -m 0755 Bin/DeepSeekSearch_v0.2.0_linux_amd64 Bin/DeepSeekSearch.new
mv Bin/DeepSeekSearch Bin/DeepSeekSearch.old
mv Bin/DeepSeekSearch.new Bin/DeepSeekSearch
./Bin/DeepSeekSearch -check -config Config/config.toml    # 配置兼容性同 §7.1
```

| 问题 | 答案 |
|---|---|
| 生效时机 | **下一次 spawn**。已在运行的 stdio 会话继续执行旧 inode（mv 不影响已打开的 fd），不会被打断 |
| 多个客户端怎么逐个生效 | 不需要逐个操作 —— 各客户端在下次新会话时自然拿到新版本。要求立即生效时，在该客户端里结束会话/重启客户端即可；批量做法：`pkill -f 'Bin/DeepSeekSearch'`（客户端会自动重新 spawn 新版） |
| 回滚 | `mv Bin/DeepSeekSearch.old Bin/DeepSeekSearch`，同样在下一次 spawn 生效；配置回滚同 §7.2 ② |
| 配置与缓存 | 所有 stdio 进程共享同一份 `Config/config.toml`、`Config/.env` 与 `Data/Cache.db`（SQLite 跨进程共享），升级前 `-check` 与配置备份的要求与 §7.1 完全相同 |

## 八、卸载（先移入回收目录，人工确认后才删）

🔴 **MUST NOT 直接 `rm -rf /mcp/DeepSeekSearch`**。该目录下有 `GitHubSrc/`（git 仓库）与 `docs/`（唯一真源文档）—— 对单人维护的项目这是**唯一副本**，误删不可恢复。卸载 MUST 两段式：先停服并**整体移入回收目录**，人工确认「已 push / 已备份」后才删回收目录。

```bash
# 0. 前置确认（三项全过才允许继续；任何一项不过 → 先补 push/备份）
cd /mcp/DeepSeekSearch/GitHubSrc
git status --porcelain                    # 期望无输出 = 工作区干净
git log --branches --not --remotes --oneline   # 期望无输出 = 全部提交已推送远端
tar czf "$HOME/backup-deepseeksearch-docs-$(date +%Y%m%d).tar.gz" -C /mcp/DeepSeekSearch/GitHubSrc docs   # docs/ 无论如何都先备份一份

# 1. 停服务、摘守护（按现行方式清理；PM2 与 systemd 各自一套）
pm2 delete DeepSeekSearch && pm2 save     # PM2 形态（本机现行）
# systemctl disable --now deepseeksearch  # systemd 形态（备选）
# rm /etc/systemd/system/deepseeksearch.service && systemctl daemon-reload

# 2. 移入回收目录（不是删除）
TRASH="/tmp/deepseeksearch-uninstall-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$TRASH"
mv /mcp/DeepSeekSearch "$TRASH"/
echo "已移入 $TRASH —— 请再次确认 GitHubSrc 已推送远端、docs 备份可用，然后手动执行: rm -rf $TRASH"
```

程序不在项目目录外写文件，所以移走目录即等于卸载干净。**MUST 确认没有 `~/.deepseeksearch/` 之类的目录**（本版本不创建）。回收目录放在 `/tmp` 是为了让「忘了删」也不占项目盘，且重启后系统会提示清理 —— 但**确认期不要依赖 /tmp 的自动清理**，删与不删都必须是人工动作。
